## 快速开始与目录结构

常用步骤：更新原始分析Excel和必要的车型映射 → 在 `scripts/generate_html` 下运行 `python main.py` → 打开生成的HTML → 切换主体、模块与周期 → 有异常时沿来源查看底表和日志。

```text
订单分析/
  input_file/销量预测输入文件/   旧格式参考及映射文件（兼容读取）
  output_file/                  当前分析Excel输入，同时存放默认生成结果
    鸿蒙智行销量数据汇总.xlsx    自动生成的预测数据汇总
    鸿蒙智行订单分析汇总.html    自动生成的离线看板
    log/                        每次运行的独立日志
  scripts/                      代码仓库
    config/                     本地业务配置目录，整个目录不纳入Git
      小订及首销数据整理.xlsx    首Sheet统一维护代际、版本及属性
    generate_html/
      main.py                   正式入口
      config.json               页面及构建配置，支持注释
      core/                     Excel解析、数据结构、输出、校验
      modules/                  各业务模块
      templates/                HTML、CSS、JS和前端计算
      tools/                    预测汇总刷新等辅助工具
      tests/                    数据与页面回归测试
```

`output_file`在本项目中既接收上游生成的分析Excel，也存放本程序输出，不是所有文件都可以删除的临时目录。不要直接编辑自动生成HTML或销量汇总：下次main会覆盖它们。应修改原始数据、配置或生成代码。

```powershell
cd "D:\05 AI脚本\PythonProject\订单分析\scripts\generate_html"
python main.py --no-open
```

去掉 `--no-open` 会在生成成功后调用默认浏览器。这里的本机数据是测试数据，验证使用正式生成结果，不另外生成测试HTML。路径定位及自定义输入输出见后文“运行”。

## 输入文件与主体识别

普通看板扫描输入目录**当前层级**的 `.xlsx`，不递归扫描子目录，忽略以 `~$` 开头的Excel临时文件。业务分类主要由文件名关键词确定，主体、时间粒度和用途再由Sheet名称及表头识别。不是任意Excel放进目录就能自动变成同样的业务分析。

| 文件名包含的关键词 | 主要用途 | 常见Sheet结构 |
| --- | --- | --- |
| 大定选配比例 | 订单总览、大定选配 | 主体名＋by天/by周/by月，及对应图表Sheet |
| 锁单选配比例 | 订单总览、锁单选配、预测平销来源 | 主体名＋by天/by周/by月，及对应图表Sheet |
| 小订选配比例 | 小订选配、小订节奏、预测小订来源 | 主体名＋by天/by周/by月，及对应图表Sheet |
| 首销期订单节奏 | 首销节奏、预测首销实际来源 | 一级或二级代际名＋by天/by时；多版本按二级代际区分 |
| 小订退订 | 小订节奏、预测小订分时等来源 | 主体名_日度退订、_小订分时退订、_选配退订 |
| 订单7级转化 | 同批订单转化漏斗 | 周/月周期及七个阶段的数量表头 |
| SKU收敛度 | SKU集中度与组合 | 主体名_SKU、主体名_组合等 |
| 选配金统计 | 选配金额、付费占比与权益 | 选配渗透率、付费选配占比、渗透率排名等 |

同类文件可以同时存在，例如不同年份的大定选配比例文件，全部纳入；重叠值不默认累加。跨半年/跨年边界周的特殊规则见“同类多文件合并”，该底层规则不只服务预测，也影响实际看板。

主体分集团、品牌、代际，由原始Sheet动态发现；销量汇总中的有效目标代际会补入选择框。不要求新车型出现后手工修改快捷按钮名单。每个主体的可用模块和粒度取决于实际数据：缺少所需表型会使模块不可用，不能强行展示空看板。

**数据入口需区分：**订单总览、选配、转化、SKU、选配金、节奏等普通看板仍读取对应分析Excel；销量预测主要读取自动生成的“鸿蒙智行销量数据汇总”。这份汇总只收集预测需要的数据，不替代所有业务Excel，也不复制所有SKU或选配金明细。

Excel公式以文件保存的缓存结果读取，Python不会启动Excel重新计算公式。公式显示有值但程序读不到时，应先在Excel中重算并保存，再生成。数字、日期和百分比应保留原始类型及格式，不要为了页面显示把数量列改成带单位字符串。

## 看板模块说明

### 订单总览

回答“当前周期下单、留存、锁单和交付怎么样”。支持实际可用的日、周、月，核心KPI为大定、留存大定、交车锁单、已交付。

当前总览要求同主体、同粒度的大定选配与锁单选配数据同时存在，周期取两者交集并排除总计等汇总标签；只有一类文件或周期未对齐时，不一定能构建该粒度总览。

- 大定、已交付主要取当前主体的数据Sheet；留存大定和交车锁单的趋势及总览口径优先使用对应图表Sheet数据，具体来源可点开核对。
- 展示留存大定与交车锁单趋势、门店渠道锁单量、可用的锁单结构，以及周/月经营指标与环比。
- 集团层增加符合条件的车型涨跌幅排行；总计/累计等汇总周期不当普通周期参与该排行。
- 集团/品牌自身KPI并不是把页面列出的所有代际再次求和，避免“汇总代际”和分代际重复计算。
- 总览口径校验用于发现数据Sheet、图表Sheet或结构分项的不一致。出现警告先比对相同主体、粒度、周期、指标，不能只因数值不同就改成相加。

### 小订节奏

回答“小订如何随天/小时变化、留存与退订发生在哪里”。当前构建需要同主体的小订选配by天和日度退订，分时与选配退订表按可用情况增加展示。

核心KPI为小订期累计、累计留存小订、累计退订和阶段留存率，附日节奏、分时以及可用的选配退订分析。

必须区分“按小订日期追踪的退订”和“取消发生日的退订”：分时退订可按下单日期聚合订单及其退订；日度退订反映当天取消的订单，可能并非当天新下单。不能用“当天下单−当天取消”无条件推导同批留存。分时缺相应日期时有日度退订展示回退，但来源不同，不应把两者视为同一批次指标。

当前代码逐日留存实际按 `max(该日采用的小订量−该日采用的退订量,0)` 计算，再求阶段合计；退订有分时按下单日期聚合值时优先使用，否则回退日度值。因此发生回退时，该页留存是这个混合来源算法的结果，不能宣称已经完成严格的同批订单留存追踪。

### 首销节奏

回答“首销已发生的订单来自小转大还是直接大定、转化走到哪里”。展示累计大定、累计留存大定、累计小转大率、累计直接大定占比、完整指标矩阵和可用的小时节奏。

“首销订单来源”图按当日直接大定和当日小订转大堆叠，柱顶为当日来源合计，不读取累计数量；周视图对应当周来源。比例线仍读取累计小转大率（累计小转大÷总小订）和累计直接大定进度，数量与比例口径在图例分别标明。缺失分项保留缺口，不用累计值替代。顶部累计KPI与完整指标表仍保留原口径，多阶段视图同样按各期独立展示当期来源。

累计小转大率＝累计小转大÷总小订；累计直接大定占比＝累计直接大定÷累计大定。支持已识别的多期首销：各期独立计算，并可展示多期汇总；多期小转大率按各期总小订加权，不直接平均各期百分比。这是实际节奏分析，与销量预测里的未来估算分开。

### 订单7级转化

顺序为：大定 → 留存大定 → 销售锁单 → 交车锁单 → 已发运 → 已到店 → 已交付。按周/月订单批次读取，同一行追踪同一批订单，不代表七个阶段各自当天新发生量。

```text
总转化率 = 本批已交付 / 本批大定
某阶段总占比 = 阶段数量 / 本批大定
阶段转化率 = 阶段数量 / 前一阶段数量
阶段流失 = max(前一阶段数量 - 阶段数量, 0)
```

展示漏斗、批次矩阵、最大阶段流失及流失占比。大定到交车锁单、交车锁单到交付的时长按源表读取，不从数量反推。列按表头名称识别，缺少七阶段必要表头时不按固定列号猜测；时长字段缺失则留空。普通模块部分数值使用安全转换和除零保护，页面0不一定证明原表明确填写0，排查时需看底表，不能套用预测模块更严格的缺失处理结论。

### 大定选配、锁单选配、小订选配

三页共用结构分析逻辑，但订单母体不同：大定选配关注大定/留存大定，锁单选配关注交车锁单/已交付，小订选配关注小订/留存小订。不要把三页同名配置的占比当作同一个分母。

展示外观、内饰、版本、能源、电池等实际存在维度的结构全景、各维度TOP1、偏好变化排行及可用的电池包周/月历史。核心结构KPI包括维度数、活跃选配项、最高配置占比、高集中维度数和最大结构变化。

占比变化以“百分点”表达，例如20%到25%为增加5个百分点，不是增长5%。高集中维度按TOP1占比≥50%判断。多个不同维度分别描述同一批订单，不能把外观占比与内饰占比相加成总占比。

### SKU收敛

回答“销量是否集中于少数完整配置组合”。展示有效SKU、TOP3/TOP5累计锁单占比、覆盖80%所需SKU数、TOP1～TOP15周度累计占比、组合热力图、排行和长尾分布。

SKU是配置组合，不等于单一外观或内饰选项。长尾分布关注单周占比≤5%的SKU。跨文件合并数量不代表TOP排名、覆盖80%所需SKU等非加法指标也能直接累加；不能从缺少完整组合分布的数据猜出新的收敛排名。

### 选配金

回答“用户选了多少金额、实际支付多少、权益影响及选配渗透率如何”。代际页展示平均选配金额、平均实际金额、最高付费选配占比、权益金额，以及金额段月度结构、选配项热力图、权益和版本金额对照。

品牌页侧重覆盖代际、高频选配项、金额段结构和汇总KPI。需注意品牌“平均选配金额”当前为有效版本金额的算术均值，不是按订单量加权的客户均值。权益金额与实际支付并非同一指标，不能把权益直接当收入，也不能把渗透率当付费率。

不同车型金额段可能不同，页面按存在的金额段对齐；月度表保留月份及金额档位两层含义，不能把总计列错认成某个月份。

### 导入分析

用于检查“哪些Sheet被识别、被哪个模块使用、哪些结构尚需配置”。展示已识别数据、待归类数据及需核查状态，如无数值、疑似只有表头、尚未被看板使用等。

这里的“导入”是生成时扫描Excel，不是网页上传原始业务文件。未知结构仅提供通用预览，不承诺自动生成正确业务口径；预览最多取前80行、24列，数值计数也有预览范围限制，不能据此判断整表规模或总量。

### 底表中心

用于按文件、Sheet查看源单元格，搜索、冻结行列及导出CSV。保留常见Excel数字格式的显示含义，便于从图表来源定位数据。

底表是生成时嵌入HTML的数据快照，不会直接修改原Excel，也不保证完整复刻合并样式、图片和所有Excel高级对象。业务看板合并多文件后，底表仍保留原文件供追溯；不要把原文件的重叠行再次累加。

### 销量预测

分小订、首销、平销三个阶段，分别提供结论、依据、打分和人工参数。其数据真实性、阶段优先级、终局计算、日历及渐进分配规则较多，集中放在本文后半部分；普通模块的历史经营KPI不能当作预测结果直接替换。

## 页面操作与来源追溯

1. 顶部选择集团、品牌或代际；“新车型”行是过滤后的快捷入口，不是完整主体清单。盲订等特殊口径快捷按钮隐藏时，下拉框仍可查询。
2. 左侧选择业务模块。灰色/不可用通常表示当前主体缺少所需表型，先检查输入和导入分析，而不是复制别的车型填充。
3. 日/周/月及右侧周期下拉只显示当前模块支持的范围。首销、小订节奏或预测窗口有自己的日期逻辑，不保证所有模块都有相同周期。
4. 点击来源入口核对文件和Sheet，必要时跳到底表中心查找相同主体、日期、指标。看板和底表若口径不同，先确认是否为累计/当期、订单批次/发生日、图表/数据Sheet差异。
5. 更新Excel后运行main再刷新HTML。页面显示的生成时间用于识别快照新旧；单纯刷新浏览器不会重新读取磁盘上的Excel。

离线文件包含业务数据及底表内容，发给他人等同于分享相应数据，不只是分享截图。外部预测导入和人工草稿保存在本机浏览器，不能保证随HTML一起传到其他电脑。

## 配置项与运行参数

`config.json`由项目自己的加载器读取，支持 `//` 和块注释；这不是所有JSON工具都能直接接受的严格JSON。

| 配置 | 含义 |
| --- | --- |
| title | 页头与浏览器标题 |
| chart_render_mode | `generated`按数据生成内置图表；`original`使用原始Excel图表图片的相关路径，不意味着所有页面原样复刻Excel |
| refresh_sales_forecast_data_before_build | 生成前是否刷新预测汇总，默认true；关闭后需自行保证汇总最新 |
| forecast_as_of_date | 预测判定日期，空值用当天；不修改原始数据，不是所有实际看板的全局筛选 |
| build_manifest_mode | off/compact/full，决定是否生成诊断清单；off时清理旧清单避免误读 |
| module_order / module_labels | 导航顺序和名称；修改名称不会改变模块取数逻辑，底表入口固定在最后 |
| grain_labels | 日、周、月显示名称，不改变日期聚合口径 |

| 命令行参数 | 用法与注意点 |
| --- | --- |
| --input | 指定当前分析Excel输入目录；不等于同时迁移所有预测历史输入路径 |
| --output | 指定HTML输出文件，日志及诊断输出结合正式入口规则处理 |
| --no-open | 生成但不自动启动浏览器 |
| --disable-sales-forecast | 仅本次生成将销量预测导航置灰且不可选，跳过预测汇总刷新及预测计算；不修改config.json，不带此参数的后续运行保持正常 |
| --check | 正常生成后若有校验警告返回非零退出码；不是只检查、不生成 |
| --debug | 输出更多解析及多文件来源细节，排查后通常关闭 |

不要仅凭退出码判断HTML是否写出：`--check`下可能生成成功但有告警而返回1；真正的异常会在日志里保留堆栈。生产使用前仍需理解并处理相关数据告警。

## 日志排查与性能

每次运行日志位于输出相关目录的 `log/generate_html_YYYYMMDD_HHMMSS.log`，通常在默认 `output_file/log`。先看输入输出路径、识别主体数、Excel读取失败、模块异常，最后看生成结果及耗时摘要。

| 现象 | 建议排查 |
| --- | --- |
| 顶部没有某车型 | 文件是否在输入目录当前层、是否为.xlsx、文件关键词与Sheet主体是否识别、预测目标是否进入汇总 |
| 某模块灰色 | 当前主体是否具备模块需要的Sheet和必要表头；查导入分析的消费状态 |
| KPI与图表不一致 | 相同周期下对比源数据Sheet和图表Sheet，核对净大定/留存大定名称及真实业务含义 |
| 多文件冲突 | 是否重复导出相同业务键；默认保留首个有效值，不是按文件修改时间覆盖 |
| 跨年周未相加 | 看文件实际by天范围是否准确衔接；30天图表窗口不能替代全年明细范围 |
| 表有公式但页面空白 | Excel是否重算并保存了公式结果；是否只有样式没有有效值 |
| 生成成功但--check返回1 | 看本次告警，而非反复运行期待消失；历史警告文件不代表当前结果 |
| 生成慢或HTML很大 | 看Excel加载、模块生成、底表整理、HTML输出分项耗时；超大有效底表会增加载荷 |

普通日志完整打印预测问题及原始数值冲突；来源读取过程、正常回退等排查信息可使用debug查看。`.cache`仅用于本次运行复用，main结束会清理，不能把它当必须手工维护的业务输入。底表压缩、读取/匹配缓存及可选清单控制用于减少重复工作；完整业务数据仍需解析，不应通过只读取第一个同类文件来提速。

日志先判断统计口径，再判断数值差异。真实冲突按“冲突类型、双方来源文件及原始Sheet、指标类别／业务块”合并为WARNING，不逐单元格或每个分类/SKU刷屏。选配比例的同一维度分别聚合数量、占比（例如动力/数量与动力/占比），不混淆两种口径；SKU按订单数量、累计占比等原始业务块聚合，原始SKU键仍用于取数，不改变去重、优先级或计算。每组保留冲突数量、完整周期、涉及业务行数、双方定位范围及首处坐标/数值；不重复打印完整SKU配置名称和同一文件名。不只展示3个周期，也不要求debug才能看到问题范围。相同物理单元格、业务键及数值被重复检查时不再打印；刷新子进程与网页主进程相同的WARNING记录也只输出一次。ERROR和异常堆栈不去重，末尾统计实际输出的问题记录，续行不重复算作新问题。

连续日期／D序号／TOP排名压缩为范围，不跨缺口；空表头拼接形成的`/23WK23`先去除两端空分隔符再压缩周范围。省略日期按0产生的虚拟位置单独按日期范围和所在行表示，不逐天展开。零散真实坐标很长时用“单元格定位区间＋实际涉及数量”定位，明确标注区间包含非冲突单元格，不宣称整个矩形均冲突；大量虚拟零位置也明确为行定位区间、非逐格明细，不伪造缺口或对应关系。

| 级别 | 使用条件 | 示例与处理 |
| --- | --- | --- |
| ERROR | 读取或生成失败、无法继续执行 | 保留完整异常堆栈、输出路径和失败退出码 |
| WARNING | 可比周期的真实数值冲突、字段非法、缺项导致功能受限、无法确认必要统计范围 | 说明对象、字段、日期/周期、来源位置和实际影响；全部问题可见 |
| INFO | 正常进度、可确定的日期推导、已确认的边界周分段、不同文件汇总口径说明 | 描述采用的来源或处理及限制，不将正常差异当作错误 |
| DEBUG | 读取候选、字段回退、初读缺项、匹配细节 | `python main.py --debug --no-open` 同时启用刷新工具细节；独立刷新使用 `python tools/refresh_sales_forecast_data.py --debug` |

冲突规则适用于原始表与图表：相同键且相同值正常去重、字段互补正常合并，都不告警。同一文件内同业务键的同一指标数值不同才告警，按原始Sheet对和业务块汇总；临时来源Sheet及SKU分块/选配金表头重排后的坐标还原到原始Sheet。跨文件的“总计、总计占比、近N天”等列没有共同统计窗口，不作数值冲突，保留已有取值规则和原始底表。仅机器浮点尾差（相对/绝对容差均为1e-12）不告警，不舍入或改写实际数据。

边界周只有文件实际日期范围证明两段在12/31→1/1或6/30→7/1衔接时才可按原规则合并数量。无法重算的SKU累计比例/排名保留优先来源，以INFO说明这是分段来源值，不宣称全周合并指标。缺少范围证据时打印“统计范围待核对”WARNING，按文件对、原始Sheet对、原因收集该Sheet所有数据块和受影响周期，统一输出，不再每个SKU数据块打一条；记录实际差异数量和定位范围。已知覆盖重叠或同一文件已经跨界时，仍保留真实冲突告警。文件名中的年份不是范围证据。

导入分析中同一主体、文件、模块、异常原因及规模/数值状态完全相同的空Sheet合并列出by天/by周/by月等全部Sheet；不同对象、原因或规模保持分别提示，页面诊断表和KPI数量不变。生成校验的来源缺失继续为WARNING，用主体名称、模块名称、页面位置、缺失字段替代不易识别的generation hash；同原因/位置合并列出所有受影响主体，不因“只是元数据”而隐藏追溯问题。

预测刷新使用实时管道转发日志，时间为事件到达主进程的时间，不再等刷新结束后统一补打；去掉重复的`[WARNING]`/`[ERROR]`前缀，异常堆栈继续按ERROR输出。openpyxl的已知Unknown extension／Conditional Formatting extension提示改为简短INFO格式兼容说明，并省略对应的`warn(msg)`源码续行；其他第三方警告仍保留WARNING。小订by天没有合计列、正常用全部日期列求和为INFO，不是数据错误；连续缺失天数如D1至D186写作D1～D186（共186天）。计算、来源优先级、比例重算规则与日志判定独立。

整理表初读缺终局、缺曲线、来源回退和D1逐来源排查属于DEBUG信息，不代表最终汇总缺数。小订已结束日、首销条件、已结束历史留存／锁单缺项及小订总量差异在多来源汇总完成后校验；缓存命中跳过刷新时也检查最终可见数据。未结束日期不要求终局，无小订车型不检查小订字段，真实0不视为缺失。严格 `--check` 仍会对最终告警返回非零。

平销历史与首销使用相同的维护窗口：明确截止日期优先，只有截止为空且有明确开始日、正整数天数时才推导截止日。周表省略整周时，完整真实日可汇成周数量；没有车型日记录但文件覆盖完整七天时，省略周为0。显式空白、非法数量和覆盖不完整的周保持未知。未知周不再清空其他有效周，只跳过跨缺口环比，周序号保留实际时间间隔。

体积很大的Excel需先检查是否包含无用的巨大格式区、重复导出或不必要业务明细；是否拆文件应以来源和业务边界为准，不能为了性能丢弃历史。缓存不计算Excel公式。HTML超过35MB时入口会给出体积提示。

## 代际名与二级代际名

`scripts/config/小订及首销数据整理.xlsx` 的第一个Sheet统一维护属性和事件窗口，第一行使用 `代际名`、`二级代际名`，以及产品档位、能源类型、发布类型、小订发布时段、首销发布时段、小订开始／结束日期、开始大定日期、小转大结束日期、首销期天数等字段。独立 `车型基本信息.xlsx` 不再是默认输入，也不会因它仍留在目录中覆盖新整理表。显式 `--mapping` 仅用于旧格式兼容。

- `代际名`是一级身份，例如“问界 M7 2024款”，用于顶部下拉框、新车型按钮、实际经营看板及平销预测。
- `二级代际名`维护完整名称，例如“问界 M7 2024款 Ultra版”；无多个事件时留空。同一一级代际可有多行，但二级事件名称须唯一，且分别维护自己的日期、真实数量和总量。
- 小订退订分析、首销期订单节奏的Sheet可使用 `问界 M7 2024款 Ultra版_日度退订`、`问界 M7 2024款 Ultra版_小订分时退订`、`问界 M7 2024款 Ultra版by天`／`by时`。其他选配比例等原表仍按一级代际维护，不要求拆版本。
- 后续历史数量／进度Sheet同样使用代际名。支持二级身份列放在任意位置：有二级时按二级事件读取，D列仍按D编号识别；列位调整不会让D1错位。源表中的重复数量／比例表头只用于分段识别，不作为数据行。

只有小订节奏、首销节奏、销量预测的小订／首销需要事件切换。右上角显示“Ultra版 · 日期范围”，切换事件会同时切换真实值、参考指标、预测日期和本机人工参数；网址保留事件选择，后退／刷新可恢复。小订节奏存在多个二级阶段时也提供“全部阶段”：合计数量、按合计留存／合计小订计算留存率，各阶段曲线仍独立展示，不平均比例或拼接不同事件曲线。无二级代际的车型保持原有单事件流程。

一级小订选配比例by天仍遵循原有最高优先级，但只把日期落在**唯一小订窗口**的值归入该二级事件；窗口重叠时不能拆分一级总量，不向两个版本各复制一份，而是记录诊断并按各版本小订分时／整理表补缺。一级大定／锁单数量也不会复制给多个首销事件。只有同一级内、确定互斥的二级事件数量才可合并；同一事件跨文件的重叠数据仍按既有冲突规则，不重复累加。

平销始终按一级代际合并：平销起点为各已确认首销结束日的最晚日期＋1天；当前平销实际直接读取一级代际锁单选配比例。首销关联参考合并各二级事件的真实逐日数量，重叠自然日合并确定的分版本数量，事件间不属于任何首销窗口的空档不伪造为首销零销量日。大定到锁单率用合并锁单总数÷合并大定总数重新计算，不平均各版本比例；任一必要组成未知则保留未知，不能补0。所有版本窗口未能确定时，不猜测合并平销起点。

整合基本信息后，首Sheet也可维护无小订、直接大定的车型：现代格式按小订日期／小订正数或显式 `有小订` 判定，不因“总小订为0／缺失”报异常。`有小订=否`可明确声明无小订；已知有小订但日期尚缺可用`有小订=是`声明，系统仍精准提示该事件时间缺失。旧版小订专用车型表继续按原有维护集合识别。无小订车型保留首销方法一及无小订方法二／平销预测，不要求小订转化率等无关字段。

无小订车型无需新增输入文件。在上述首Sheet增加一行，维护`代际名`、`有小订=否`、`首销开始日期`、`首销结束日期`；结束日也可用`首销期天数`代替。例如开始2026-09-01、结束2026-09-30（含首尾30天），平销自动从2026-10-01开始，暂不支持独立覆盖平销起点。旧列名`开始大定日期`／`小转大结束日期`继续兼容。首销节奏缺失时，无小订车型可从大定选配比例by天补真实大定，直接大定等于总大定、小转大为0；不拿留存大定替代总大定。已结束D1有效、已过日期完整且参考完成率可用时，方法一可正常预测。物理文件覆盖内省略日期按0，明确空白和未更新日期仍保持缺失；有小订车型的既定取数优先级不变。

汇总可见业务Sheet统一保存`代际名＋二级代际名`，日期和D指标不靠名称猜测归属。网页销量预测只从汇总恢复这些数据，不重新补读原始订单文件。名称迁移应先备份原始整理表，并验证既有数量、日期、公式及格式均未改变；备份放子目录，不参与默认当前层级扫描。业务输入及生成结果不进入代码提交。

## 销量预测使用概览

本机输入为测试数据。修改后直接运行 `python main.py --check --no-open` 更新默认的 `output_file/鸿蒙智行订单分析汇总.html` 和销量数据汇总，不另建预览/测试 HTML；网页验证直接打开该生成结果。

小订、平销预测依据使用与首销一致的参考卡片：主参考、辅助参考、独立权重、评分对比和图表对比车型。额外勾选只改变显示，不影响预测；权重按有效参考自动归一。小订分别选择累计完成度、到天基础曲线和 D1 分时参考，平销参考用于完整周的量级与趋势，到天仍主要按工作日、周末和节假日系数分配。

小订 D1 分时评分不使用历史 D1 绝对量：发布时间20%、已发生小时的新增量归一化斜率50%、前几小时累计占比30%，缺项按有效权重归一。曲线从该车型首个有效小订小时开始（作为发布时间参考），发布前留空。预测将历史曲线按发布后相对小时对齐，结合当前累计进度和最近最多3小时的增量估计未来小时；D1终值＝已发生真实累计＋未来小时预测。小订预测终局实时传入首销方法二；方法一仍等待首销真实进度。

同一一级代际有多个小订／首销事件时，用“二级代际名”区分，例如 Ultra版、Pro版、增程版、纯电版。事件、日期、参考曲线和人工参数分别保存；不再依赖“第1期／第2期”或行顺序。顶部主体选择仍只显示一级代际，事件在右上角以“版本 · 时间段”切换。

原始进度表只填部分日期时，读取首个数量表，逐格保留已有数量及真实0，未来空白保留为空；后续比例表不能覆盖首个数量表。已维护的同车型别名按日期补空，冲突保留首个非空值并提示。总大定仅在同一天小转大和直接大定均已知时补算。累计指标保留完整已填前缀，遇到内部缺口后的累计及未知终局分母对应的完成度留空，不把当前累计冒充最终总量。

## 逐日外部预测导入

三个阶段共用一个导入模板，支持 .xlsx（第一个可见工作表）和 UTF-8 CSV：

`车型（代际）｜日期｜预测小订｜预测大定`

“预测大定”是**总大定，不是留存大定**。两种数量可分别留空，但每行至少有一种非负整数；零有效。一次导入当前车型记录，三个阶段共享：小订展示小订列，首销展示总大定列，平销将总大定乘当前“大定到锁单率”后展示锁单。页面说明转换率与来源；转换率缺失不当0，保留原始导入数并提示。旧三列“预测数量”模板仍兼容，按当前入口解释为小订或总大定；旧浏览器已存的平销锁单记录仍按原口径保留，不重复乘率。

不再选择“纳入范围”：已过日期的预测保留，与实际数据同时展示；当天实际单独标识为未完成日快照。各图只显示本阶段日期，首销不混入平销日期；阶段交界同日允许小订和大定分别存在。未匹配阶段的导入记录保留，但不出现在该阶段曲线中；修改日期参数后重新切分展示。缺失值留空，不补零。

按“当前车型＋指标＋日期”合并更新，来源逐条保留，不累加同指标重叠数据；整份替换需确认。无效日期、负数、两列均空、同车型同日重复行拒绝整次导入。单文件最多5MB、20000行，合并后最多20000条指标记录（同日同时填写两列计2条）。导入仅用于独立对照，不改变系统预测或真实值。

人工参数与导入保存在当前浏览器、当前HTML路径下，不上传。“恢复系统推荐”按钮直接可见，清除**当前车型三个阶段**的人工参数、参考和权重草稿，重新采用本次数据推荐；不删除外部导入，不影响其他车型。清除导入另有按钮。存储损坏、空间不足给出提示，不阻断计算。

预测依据中的数值参数统一提供逐项“恢复”，不再使用“采用参考均值／采用参考完成率”的整组按钮。输入后自动重算，无须点击应用；首销转化率、直接大定占比和锁单率分别记录人工覆盖，修改其中一项不会冻结其余项。恢复只清除此项覆盖：参考类参数重新跟随当前主辅参考及权重，日历系数恢复工作日1／周末1.15／节假日1.3，差额权重恢复留空自动分配。真实值或上游预测联动的只读字段不能手动恢复。旧版整组覆盖草稿继续保留原设置，逐项恢复后可独立跟随参考。

预测参考卡片的主参考、辅助参考及两个权重也分别提供“恢复”。车型恢复为当前目标、时间和有效数据下的系统推荐；权重恢复主70%／辅30%。每次只恢复所点的一项，保留其他手工参考及权重，立即重算并保存；“图表对比车型”仍只影响展示，不参与预测。累计进度、到天基础曲线、D1分时、每日斜率及平销共用参考均使用同一控件样式。

三阶段日历与分配控件共用同一布局：日历系数一组、逐日差额权重一组，默认“0、0.5、1、1……”的简述常显，详细规则可展开。首销预测参数与公共参数在宽屏并排，窄屏顺序排列；小订和平销按实际控件数量布局，不为不存在的另一组参数预留半屏空位。不改变终局计算、日历系数的应用次数或逐日分配口径。

三阶段评分页优先展示推荐与候选排名，单车评分明细按行展开，完整评分规则及缺失处理统一放在底部折叠区；展开只改变显示，不重算评分。窄屏候选行转为带字段标签的卡片。预测依据图表的长口径说明可展开，周期拉伸说明仍有明确入口，以减少左右图表因说明长度不同造成的错位。

车型与时间参数保持直接展开。顶部至“预测结论 / 预测依据 / 预测打分”采用紧凑响应式布局，生成时间、字段标签和键盘焦点提示保留。主体下拉框和普通模块共用集团／品牌／一级代际列表，不另维护预测专用名单；可用模块仍按实际数据决定。集团／品牌入口沿用所属工作区的默认预测车型，不表示生成集团／品牌加总预测。

顶部可分别调整“小订开始日期→小订发布时段→小订天数”和“首销开始日期→首销发布时段→首销天数”。两个发布时段在原整理表首Sheet分别维护，汇总与网页只读取对应阶段字段；只支持上午／下午／晚上，沿用时段锚点9／14／19时。原表有值优先；留白时在汇总生成阶段从该阶段D1首个正数订单小时确定起点（小订用小订量、首销用总大定），保留精确小时，0单与空值不算开始，D2及以后不参与补推；没有正数小时就不猜测。两个阶段不互相回退，也不读取旧`发布时段`。汇总优先保留原维护时段及真实by时明细，并在车型基本信息写入“小订开始小时／首销开始小时”及各自来源；表格有时段时写9／14／19，留白时在汇总生成阶段补齐D1首个正数订单小时。网页默认直接使用汇总起点，人工修改日期／时段后才按汇总明细重算。原时段留白且有D1依据时，同时回填发布时段：0–11时为上午、12–18时为下午、19–23时为晚上；以“开始小时来源”区分原表维护与D1推断，精确小时不被分类时段的9／14／19时锚点覆盖。原时段留白且无D1依据时仍为未维护。小订天数、两个发布星期、平销开始日期也在汇总生成时由明确的阶段日期计算；没有日期依据仍留空。总量、比例、D1/D2和累计曲线继续从同一份多来源已结束日数据生成，未知终值及分母不补估，前端交互预测不写入真实汇总。修改日期或天数会重新计算该阶段结束日（开始＋天数−1）、进度、参考选择和未来分配，首销修改还会同步平销起点；绝对日期上的已发生销量不被移动或改写。修改发布时段会进入对应阶段的分时对齐／参考评分。档位、能源、发布类型等影响推荐，若推荐与公式输入没有改变，最终数量可能相同；已结束阶段保持真实总量，不因参数编辑重算历史。无小订车型的小订参数禁用；首销日期／天数无效时提示具体条件不足，不默认补一天。参数和人工参考仍按车型／二级事件独立保存在本机，可用“恢复系统推荐”清除。

首销总大定不扣大定退订，锁单单独计算。小转大率为累计小转大除以总小订；实际小订退订率仅显示已有真实值，未来缺失不按0显示。预测依据中的真实区间用实线、估算和预测区间用虚线。

三阶段“预测依据”的折线图共用首销图表格式：当前真实蓝色实线、当前预测绿色虚线，主辅历史参考橙/紫实线；坐标、数值标注、最新值图例一致，缺值断线、真实0保留，窄屏仅在图表内部横向滚动。小订展示累计完成度、到天基础曲线和D1分时累计图，D1进行中使用预计全天小订作分母，D1结束后使用同日完整真实小订；真实线仅绘制已采集小时，后续小时预测单独用虚线显示，不当成真实值。分时缺失时提示并保留可用历史参考。平销依据分别展示全首销直接大定的归一化曲线和平销完整周相对趋势，不拿历史绝对销量对比；结论图仍展示真实及预测锁单数量。主辅参考和权重参与预测，额外图表对比车型仅用于展示；不改变原始取数优先级。

阶段未开始也可预测：小订预测作为首销方法二输入；小订结束当天仍按进行中处理，即使首销开始日与小订结束日重合，方法二也承接当天小订预测终局，而不要求尚未形成的真实总小订。小订预测暂不可用时显示等待原因，不把“缺少预测输入”报成原始总小订错误；结束日过后仍校验真实总量。方法一具备真实进度后才可用。平销开始前优先承接可用的首销方法一，否则方法二，以直接大定乘锁单率估算平销量级；平销开始后维持本车型真实平销锁单优先。预测输入始终标注为预测，不混作真实订单。

读取 Excel 汇总报表，生成一个可离线打开的交互式 HTML 看板。品牌和代际从原始 Sheet 自动识别；销量预测汇总中的目标代际也会补入顶部选择框，预测页按目标清单去除别名重复。可用标签随实际看板数据决定；底表保留 Excel 单元格显示格式，支持搜索、CSV 导出和来源跳转。

## 销量数据汇总与取值优先级

`鸿蒙智行销量数据汇总.xlsx` 由 `tools/refresh_sales_forecast_data.py` 生成。生成时按阶段和字段优先级确定最终值；by天按代际/日期唯一，by时按代际/日期/小时唯一，by周按代际/ISO周唯一。网页销量预测只读这份汇总的可见单元格，不补读原始参考文件、不依赖隐藏缓存、不二次选择来源。D1/D2及后续指标从同一份多来源数量重算。

### 计算职责：保留必要派生，不重复实现

- **汇总生成（Python）**：合并原始文件、映射代际／事件、按字段优先级选数、识别真实0与未知、补齐有依据的默认字段并整理历史曲线。原始读取入口只供汇总刷新调用。
- **网页构建（Python）**：读取汇总可见单元格，转换日期和数据结构、校验预测条件、整理图表需要的参考形状及索引。已确定来源的实际数据直接打包，不再进入原始来源解析器，也不再次合并小订历史。汇总缺失或结构过期时明确报错，先由main刷新，不偷偷回退原始文件。
- **浏览器预测（JS）**：负责调参后的打分、主辅参考混合、终局与剩余量、日历影响及逐日分配。默认预测和人工调参复用同一套计算；结果仅用于页面，不回写历史实际。
- **页面呈现（JS／CSS）**：消费计算结果，负责图表、表格、状态及样式；不另写一套预测公式。必要的汇总求和、结构转换和动态预测不是同一职责，不以“全部预先算完”为目标。

首销by天存每日小转大、直接大定、交车锁单；by时保存每小时大定及源表明确提供的小时小转大、小时直接大定、小时交车锁单，不保存累计列。小时数量和完整日数量分别保留，只有by时而缺by天时也能保存已知小时分项。刷新时核对同代际／事件、同一天的小时合计、原分时快照合计与最终by天大定，再逐项核对分项数量，把可用分项名写入by天的`首销分时核对`。网页只读取这个结果，不再次猜测快照是否一致。总量相同但分项不同，也不能当成已核对。未核对的分项保持未知；既有预测算法如按参考占比估算，会在预测说明标明，不伪装成实际。已结束日实际仍直接读by天，D1及当日完成进度仍需要by时。

### 同类多文件合并

输入目录下所有匹配类型的 `.xlsx` 都参与读取，忽略 `~$` 临时文件。同类不同年份的文件按原文件路径排序（同目录即文件名顺序），不是按修改时间选“最新文件”。

- 已识别表型按车型/Sheet、指标标签及日期或周期对齐；同类 Sheet 名仅忽略空格差异，保留不同首销期标识。订单7级转化按周期、分时小订按日期和小时、日度退订按日期识别记录键，不按固定列号拼接。选配金保留月份与金额档位两层表头，每月汇总列不移到其他月份。
- 同一业务位置取排序后首个非空值，后续文件只补空白。真实 `0` 有效，不被后续非零值覆盖；相同值去重，不重复累加。图表数据同样先完成空白回退，再按原展示规则处理仍无数据的位置。
- 重叠位置数值冲突时保留首个非空值并按文件类别汇总记录“多文件数值冲突”日志；普通日志只输出多文件合并概览，`--debug` 才列完整文件名。不会把年度文件中的总计相加，也不会自动把不同首销期合并成一场活动。
- 不同日期取并集，来源保留所有参与文件；底表中心仍可查看原始文件。未知表型保留各原表，不强行套用合并规则。
- 同代际跨年平销文件合并成一份历史，避免被当作多辆参考车重复加权。
- 选配比例明细合并时，指标名称“净大定”和“留存大定”沿用总览的兼容口径，统一按“留存大定”对齐，避免旧年/新年形成两行。只统一已识别指标的名称，不改变数量，不修改原 Excel，也不把“大定”并入。前提是原表实际业务口径相同；如果退订扣减范围不同，不能靠改表头把不同口径变成同一指标。

周数据的例外：按 ISO 周（周一至周日）判断跨 12 月 31 日的周，或跨 6 月 30 日且该日不是周日的周，但“是边界周”只是必要条件。只有两个原始文件的实际数据范围在边界处准确衔接（一个截止 6 月 30 日/12 月 31 日，另一个从 7 月 1 日/1 月 1 日开始），同一业务数量字段的不同有效值才相加。范围从文件内有有效数量的逐日日期判断，无需人工维护；也支持已有明确导出起止日期。若文件本身已跨半年/跨年、日期范围重叠、有间断、与该边界无关，或只有周标签无法确认范围，均不累加，保留原优先级并提示冲突。不能凭文件名年份猜范围。第三个文件重复同一半段不再追加。来源范围随汇总暂存目录传递，网页和预测不能各自猜测。

例如 `26WK27`（2026-06-29～2026-07-05），文件A实际截止6月30日、文件B实际从7月1日开始时，140与90合为230；文件A已覆盖到7月5日时，不会再加文件B的90。跨年同理。`26WK53`、`2026WK53` 和大小写差异统一为同一周。相同值仍去重，普通周、日/月、年度总计及同文件重复键不适用此例外；真实零值可以参加加法，非法数、负数、非有限数不参加，明确空白/未来未填的日期不充当真实范围证据。

范围识别优先使用整份文件中非图表 `by天` 明细的有效数量日期及已有明确导出起止日期。`by天图表` 可能只展示最近30天，不能缩短或扩大已有明细范围；仅无有效明细/声明日期时，才回退读取逐日图表所有主体块各自的日期表头。日期支持 Excel 日期、日表头中的 Excel 序列日期、四位/两位年份文本和中文年月日。`26WK01` 对应 2025-12-29～2026-01-04，同样适用跨年衔接规则。

低销量老车型可能连续多日没有订单记录，不能用该车型最后一次成交日期代替整份文件的覆盖截止日期。范围取同一物理文件中所有可识别逐日表的有效日期并集，包括其他车型、品牌/集团汇总及明确的零数量；因此不要求每个车型都在边界日成交。若整份文件也缺少边界日期证据，仍无法区分零销量缺日与未导出日期时，不人为补出文件起止日期、不盲目累加，按普通冲突优先级处理。

该例外同步作用于选配比例表中的数量、订单7级转化的数量及趋势图总量，销量预测和销量数据汇总共用合并结果。占比不直接相加：有对应分类数量时由合并分类数量重算，否则有主指标数量时按各片段数量加权；图表占比按各片段总量加权。缺少必要分母时保留原优先值及冲突提示，不猜测分母；平均时长、均价等非数量指标仍保留原优先值，不直接相加。INFO 日志用 `[边界周累加]` 按类别汇总周日期范围、跨年/跨半年原因、数量字段数、来源文件、各文件实际日期范围及最多3个加法示例；重复读取同一图表不重复打印累加日志。底表中心的原始文件保持不变。

未合并的图表真实冲突逐项列出主体、指标、周期、双方文件与原始单元格；边界周还给出文件实际范围和未累加原因，不再截成3个周期示例。已完成同一图表校验的读取复用不重复运行校验。SKU数量块遵循同样的边界周规则，但TOP3/TOP5、80%覆盖所需SKU数等收敛指标不能把比例或排名直接相加，仍保留原优先值并说明口径；不从不完整的SKU分布猜算新的收敛排名。

### 按字段选择来源

“来源优先级”指某个字段的有效值顺序，不是只选一个文件后放弃其他来源。以下“整理表”均指《小订及首销数据整理》及其二次处理参考数据。

| 用途/阶段 | 优先级及边界 |
| --- | --- |
| 同车型、同日期的真实小订 | 整理表真实“小订by天” →《小订选配比例分析》代际 `by天` →《小订退订分析》小订分时按日汇总。整理表要求同一小订开始日期、同一代际/二级事件及维护窗口，真实0有效。 |
| 小订 D1 当前分时 | 《小订退订分析》“小订分时退订”；日合计不能冒充分时快照。 |
| 首销未开始 `before` | 真实小订与上行相同。仅小订维护窗口内有新增小订；日合计不能替代分时快照。 |
| 首销进行中 `active` | 整理表 →《首销期订单节奏》；两者缺失的大定/留存大定/锁单允许对应选配比例表最后补缺（用户确认）。退订只取《小订退订分析》，不跟随通用字段回退。 |
| 首销已结束 `ended`，以及平销引用历史 | 按数据日期所属窗口选值，不按当前页面或车型今天的阶段重排历史优先级。历史小订、首销仍用以上规则。首销结束后的日期，大定/留存大定优先《大定选配比例分析》，交车锁单优先《锁单选配比例分析》；整理表不延伸到首销后，小转大/直接大定只在首销窗口内，小订只在小订窗口内。 |
| 首销阶段未知 `unknown` | 诊断取数：整理表 →《小订退订分析》（退订）/《首销期订单节奏》（订单）→对应《大定选配比例分析》《锁单选配比例分析》。已知实际数量保留，日期不明仍不能正常预测。 |
| 平销真实销量 | 《锁单选配比例分析》代际 `by天` 的“交车锁单”；参考完整周取 `by周` 的“交车锁单”。不再读取独立平销历史文件。 |

#### 终值、D1/D2与累计曲线的补齐（2026-10-13修复）

汇总先完成真实小订量及最终总小订的补齐，再生成首销总量、比例、`首销D1D2预测指标`及后续累计曲线。不能在分母尚缺失时计算一次比例，补入分母后仍保留空值；这些表不再只看整理表最初读到的内容。

- 首销已结束：总小转大、总直接大定、总大定等优先用已按来源优先级补齐的完整首销日量合计。日量仍不完整时，保留有效维护终值；终值也缺失时，允许同代际／二级事件、同首销D1的真实累计数量补缺，必须能确定截至首销结束日的累计，不能用结束后或其他期次的累计替代。
- 《首销期订单节奏》by天中的**累计数量行**是有效来源，不是文件级“总计／近28天”列，也不从转化率反推数量。同一字段存在D1累计，或相邻两个自然日累计时，可以准确差分补当日空值；整理表真实日量和首销表明确日量优先于累计差分，选配比例补缺在后。跨缺日的累计只补对应日期的累计进度／终值，不平均摊成缺失日量。累计下降或与高优先级已知日量矛盾时，该字段累计不参与补缺，并汇总提示冲突。
- 小订转化率＝总小转大÷总小订；直接大定占比＝总直接大定÷总大定；退订率＝总退订÷总小订。退订只取《小订退订分析》，沿用真实累计基数接上后续真实日量，保留首销前已发生退订；不把首销内日退订合计误当全部累计退订。
- 小转大／直接大定累计完成度＝对应日期真实累计÷有效最终总量。日量中间有空白时，可从该日真实累计恢复后续累计计算，但缺失的单日数量仍留空。累计退订率同样使用真实累计与最终总小订。
- D1/D2按字段保留已知数量；单项完成占比、D2/D1等只依赖各自必要字段，不因另一个无关分项缺失而整组清空。已确认“小转大＋直接大定≠总大定”的结构冲突保留数量和可计算比例，但标记口径异常，网页排除对应参考。
- 汇总保存源表明确提供的日量、总量和可计算比例，包括当天快照及复盘日期之后的源表值；by天标记日期状态，车型基本信息标记小订/首销阶段与参考终值资格，D1/D2标记口径状态。网页只拿已结束日期作历史参考，进行中的已知总量不能充当最终参数。未知总量/分母继续留空，不拿当前累计或预测值冒充终值。真实0保留，分母为0不计算比例。

日数量必须是有限非负数，真实 `0` 可用；空白、非法数和负数按缺失处理并继续回退。数量收录与预测资格分开：已知分项即使与总大定不一致，也按来源保留在汇总；D1/D2结构校验、预测条件校验负责拒绝不一致的结构指标。不因同日锁单高于大定直接删除锁单。总小订作为预测分母必须大于 `0`；“0有效”的日数量规则不表示总小订为0也可以做除法预测。

周表保留阶段未知、首销开始前的已知实际周量，并标明“阶段未知”或“首销前”，不参与平销完整周参考。跨首销/平销周优先用同一份已解析日数据拆分；日数据不全时，已知原周总量仍保留，无法确认的阶段分项留空，不按比例拆分。日/周解析只扫描选配来源一次，周计算复用已收集数据和最终日取值。

最终总小订优先保留整理表明确维护的终值；缺失时使用其他来源明确提供的真实终值或完整真实小订逐日合计，没有依据则保持缺失。不通过累计小转大/转化率或累计退订/退订率反推总小订；小订进行中的预测终局按自身规则用于后续预测，不写成历史真实总量。结束后的锁单优先完整真实日合计；仅逐日不完整且同车型、同首销开始日、同天数、总大定一致时，使用汇总已确认终值补缺。

名称匹配优先二级代际名（存在时）或一级代际名精确命中。旧格式兼容只接受可唯一确认的名称／时间窗口，不把一级代际当作多个二级事件的共同别名。字段来源、退订来源和数据状态随汇总保留，可在说明、底表和日志核对。

### Excel 缓存的读取边界

`main.py` 每次运行结束（正常完成、生成失败或键盘中断）后，自动删除本次 `--input` 目录下整个 `.cache` 文件夹；默认位置为 `output_file/.cache`。缓存仅在运行期间复用，不跨次保留，所以下次运行会重新解析 Excel。清理不影响原始 Excel、销量数据汇总、HTML 或日志；目录被占用等清理失败会记入日志，不覆盖原有生成结果或退出码。为防止误删，不跟随 `.cache` 符号链接或指向其他位置的目录联接。独立运行刷新工具时不触发网页生成入口的退出清理。

`core/excel.py::load_data_workbook` 在缓存未命中时使用普通 `openpyxl` 读取（`data_only=True, read_only=False`），再缓存非空值、数据类型、数字格式和 Sheet 状态。合并区域只有左上角保留值，其他位置仍为空；不使用会暴露合并区域底层残留 XML 值的流式读取。缓存视图不保留合并样式、图片等装饰信息，也不保留纯样式空白形成的巨大网格；保证的是数据取值语义，不是 Excel 排版复刻。

缓存签名包含版本、完整路径、文件大小和纳秒级修改/创建时间。旧版本、源文件变化、损坏或缺少结束标记的缓存均重新读源文件；写入采用临时文件替换，读取期间源文件变化则不提交缓存。缓存不能计算 Excel 公式，`data_only=True` 读取的仍是文件中已有的公式缓存结果。

## 销量预测逻辑与真实数据边界

### 无小订车型与预测条件提示

- “小订及首销数据整理”中维护的车型属于有小订车型；不在该小订维护集合中的车型直接进入大定，不因总小订、转化率缺失而报异常。汇总的“车型基本信息”保存“有小订”标记，网页只从汇总读取，不根据销量为0猜测是否有小订。
- 无小订车型：小订阶段显示“不适用”；首销数量为直接大定，结构性小转大为0。方法一按直接大定真实进度和参考同期完成率推终局；方法二按有效D1大定量÷到天参考D1占比推终局，D1优先真实或当日分时估计，首销前可以人工填写。缺少有效D1输入或参考占比时，只提示该方法条件不足。两种方法继续共用到天基础曲线、日历系数和真实日衔接分配；平销仍参考直接大定趋势和交车锁单实际。
- 有小订车型：总小订未知只影响依赖该输入的方法二和小转大率等指标，不连带停止输入完整的方法一。小订进行中（含结束当天）的有效预测可作为方法二输入，但不能冒充真实历史总量。
- 首销已结束时，不再分配预测余量；完整真实总大定正常展示，小转大、直接大定等缺失分项及无法计算的比率留空。尚在首销中的必要真实分项缺失，按方法限制计算，不借参考比例补成真实值。
- 三个阶段统一使用“阶段 · 状态／原因／影响”提示，明确缺失字段、具体日期或连续范围、受影响方法；没有预测窗口、原始数据异常、未更新和不适用不能混为一个“原始数据错误”。已知实际数据始终保留查询与展示。

### 多文件周期与汇总列边界

“总计、合计、汇总、累计、近28天”等文件级汇总列不用于网页指标或预测，不联合计算，不纳入多文件数值冲突；原始底表保留原样。仅具体日期、周、月执行来源优先级、重叠冲突和已确认文件边界周累加。

当前未结束周与跨首销／平销边界周分开判断：当前周按实际更新日期保留已发生逐日合计，不要求未更新日期、更不补0；真正跨阶段周才需用逐日数据拆分，历史拆分字段不足仍留空并提示。未结束周不能当作完整周参考。

### 时间、参考与真实性

判定日期优先使用 `forecast_as_of_date`；未配置时Python用生成当天，浏览器用本机当天，跨日需重新生成以更新真实数据快照。首销开始优先取整理表维护窗口，再取首销节奏日期、历史参考日期；明确起止日期优先于天数，缺截止日且有维护天数时才推导截止日。小订起止日期必须维护，缺结束日期不猜成1天；平销开始为首销截止次日。开始日和结束日都属于阶段内，结束日当天仍是进行中，次日才算已结束。

`as_of_date` 只改变阶段判定和日期切分，不还原当时文件版本，也不自动撤销后来补录的数据。历史复盘若要严格使用当时已知的信息，需要配套当时的原始文件快照。

| 数据状态 | 参与方式 |
| --- | --- |
| 已结束日（日期早于判定日，且在阶段内） | 冻结真实数量。必须通过日期完整性、非负数及分项校验；必要数据缺失时停止对应预测，不用参考占比或预测补成真实日。 |
| 当日快照 | 只代表截至某时点已发生量；全天外推仍为估算，不计入完整日真实累计。当日预计量不得低于已发生量。 |
| 未来日期 | 预测输出或参考数据，不能提前算入真实累计。 |
| 非真实参考曲线 | 用于形状/完成率，例如“小订进度”回退曲线；不能替代目标车型真实逐日数据。 |

选配比例原始导出按连续更新约定处理：小订和平销的缺省日期，在同一物理文件可确认的更新范围与该车型阶段窗口交集内按零销量读取，不再受单车型首末成交日限制。范围取同文件其他车型、品牌/集团汇总等可识别逐日数量；多文件各自保留范围，不把文件之间未覆盖的日期补零。源表显式空白、异常数量及文件更新末日之后仍按缺失处理；没有整份文件日期证据时，退回原先单车型有效观测区间规则。平销完整周列省略时，可由七个完整真实日汇总得到零销量周；明确空白或异常的周值不被覆盖。周参考仍排除首销重叠周及当前未结束周，无法证实的周序列间断不参与周环比。

主辅参考按各自权重对有效指标重新归一加权。小订评分考察档位、能源、发布类型、窗口天数、已知小订量级；平销评分考察档位、能源、发布类型、首销锁单率。这两类自动推荐至少需3项有效评分证据，证据不足可人工选择；参考不选当前车型本身。首销按分时、转化、直接大定占比、锁单率、小转大/直接大定完成率和日曲线等任务分别选择参考，不能认为所有公式共用一辆参考车。

### 小订预测

| 阶段 | 算法 |
| --- | --- |
| 小订前 | 按产品属性、发布属性与小订窗口选参考，主辅历史最终总小订加权估计量级；D1＝总量×参考D1占比（小订前缺该占比时默认20%）。线索和互联网热度已停用，不读取旧草稿或旧汇总内这两个字段；无本车型实绩时标低置信度。 |
| D1进行中 | 用当前分时累计和最近最多3小时新增量分别估计量级，合成未来小时预测；D1预计全天＝已发生＋剩余小时预测。最终总小订＝D1预计全天÷按目标窗口重定基的参考D1占比；仅1天窗口直接用D1量。缺当前分时、真实参考分时或有效D1占比时停止，不用通用线性曲线替代。 |
| D1以后、仍在小订期 | 先检查D1至昨天的全部真实日，再以“完整日真实累计÷参考同期累计完成率”推算终局，且终局不低于真实累计。无需先知道目标车型最终总小订。 |
| 小订结束 | 按前述冻结总小订优先级收口，不再预测未来余量。逐日形状优先真实“小订by天”，回退“小订进度”时仍注明其为参考形状；没有正数可冻结总量时停止。终值可用不代表逐日完整，结束分支按总量收口，不能把参考形状当作补齐的真实日。 |

参考完成率统一保留历史D1、D2、倒数第二天、最后一天各日占比，仅对中间累计曲线按相对周期线性插值；不再截断或衰减外推。真实曲线优先，标准化“小订进度”仅作回退。剩余量按参考日增量、目标日历系数和衔接权重分配；当天已发生小订高于原预测时，先重分配未来余量，余量不足才抬升总量。

### 首销预测：两种方法独立计算

首销口径为**总大定＝小转大＋直接大定**，不扣大定退订；交车锁单另算。小转大率＝累计小转大÷总小订，直接大定占比＝直接大定÷总大定。

**方法一：按真实进度反推终局。** 分别计算：

```text
小转大终局 = max(小转大基准量, 小转大基准量 / 参考同期小转大完成率)
直接大定终局 = max(直接大定基准量, 直接大定基准量 / 参考同期直接大定完成率)
总大定终局 = 小转大终局 + 直接大定终局
```

基准量＝已结束日真实累计＋当日存在快照时的全天估算。页面真实累计只显示前一部分。参考完成率先按目标首销窗口重定基，再主辅加权；系统参考完成率过低时设0.5%安全下限并提示，也支持人工覆盖完成率。人工完成率必须大于0%且不超过100%；填写0、负数或超过100%时，方法一暂停计算并指出具体字段，不偷偷回退参考值；清空输入恢复参考值。已结束阶段仍按真实数据展示，不受此参数影响。方法一需有有效真实进度、完整已结束日期和可用参考完成率，首销前不可用。

**方法二：由小订和转化参数推算终局。** 总小订为 S、小订转化率为 c、直接大定占比为 p：

```text
原始小转大终局 = S × c
原始直接大定终局 = 原始小转大终局 × p / max(1 - p, 0.05)
总大定终局 = 小转大终局 + 直接大定终局
预计锁单 = 总大定终局 × 大定到锁单率
```

系统参数取各任务主辅参考加权值，也可人工调整。小转大、直接大定各自不能低于对应基准量，锁单不能低于已发生真实锁单。首销尚未开始且小订阶段尚未结束时，会将当前车型、当前判定日的小订预测接入方法二，明确标为预测输入。总小订非正、转化率不可用或原始数据校验失败时不输出方法二结果。

首销前D1可人工填写；系统建议为方法二总大定×历史D1占比，占比限制在8%～75%，无有效比例时默认30%。D1已结束后使用真实值，不再接受D1预测替代。进行中的当天优先 `by时`，否则可用 `by天` 当日快照估算全天并提示低置信度；只有当日允许按参考占比拆分缺失分项，并保持小转大＋直接大定＝总大定。

D2以后分时完成率优先本车型最近最多7个完整非D1日、同日历类型优先的真实分时曲线；否则借用历史D1，仍缺失时首销可用通用线性曲线并提示低置信度。首销日形状缺参考时可用通用幂衰减回退。这些只影响估算，不豁免已结束日真实数据校验；与小订D1缺分时直接停止的规则不同。

两种方法各自保留完整真实日和当日估算，分别分配自己的剩余小转大、直接大定；整数逐日合计与各自终局一致。首销结束且真实日完整时，两种方法都按真实结果收口，不再分配余量。累计小订退订只展示真实已知值，未来缺失不显示成0，也不当作“当日大定退订”。

**逐日订单来源结构（2026-10-12修正）：** 到天基础曲线、日历系数、真实日衔接及渐进差额先形成每日总大定；在不改变这些日总量的前提下，再校准小转大／直接大定的每日拆分，避免两类都沿同一形状分配而使累计直接大定占比从D1到末日保持终局比例。

- 方法一的分项形状分别取“小转大累计进度”“直接大定累计进度”所选主辅车型的对应真实日量；方法二分别取“小订转化率”“直接大定占比”所选主辅车型的对应真实日量。各组使用自己的主辅权重；额外图表对比车型不参与。
- 仅首销已结束、逐日总大定与两类分项收齐且相加一致的参考参与完整形状分配。先按历史真实日期剔除日历影响，再保留头两天／尾两天、拉伸中段并归一化。有效主辅重新归一权重，不把缺失分项补0、不用未结束车型虚构尾段；历史曲线展示仍保留已知部分。
- 将方法终局分项量乘以各自的归一化日形状，形成日来源比例目标；有真实日衔接时，从原拆分按渐进权重过渡。用有每日容量上限的比例校准和整数余数分配，使每天小转大＋直接大定严格等于原每日总大定，两类全期合计严格等于各自终局。默认首个零权重衔接日保持原拆分，后续逐渐调整；人工权重仍生效。参考走势是约束下的形状依据，不保证与参考百分比逐点相同。
- 完整真实日、当日分时滚动日及无分时但有当日快照的保底拆分不被重写；首销前D1总量保留，但来源拆分纳入全期校准。无小订车型仍为全部直接大定；只剩一天、某类剩余量为0或历史结构本身不变时可以合理出现平线，不人为制造波动。
- 缺少有效分项形状时保留原分配，并提示“订单来源分项曲线不足，保留原逐日拆分；占比可能保持不变”。结论、依据图、数值表和首销前D1提示共用同一份预测行。累计直接大定占比＝累计直接大定÷累计总大定，累计小转大率＝累计小转大÷总小订，不另造仅供绘图的曲线。

### 平销预测：只输出交车锁单

平销把本车型首销全时段直接大定规律与当前平销实际结合，历史参考只提供相对变化，不套用历史销量。

1. **全首销基准**：首销已结束时使用全部首销真实日；尚未结束但上游预测可用时，优先方法一、否则方法二的完整逐日直接大定预测，明确标为预测输入。每个日量先除以对应日期系数；规模基准为全期日历还原直接大定日均 × 同窗口累计锁单/累计总大定。不能只截取末7天或去掉D1、D2。
2. **参考评分**：全首销直接大定归一化形状55%、已有平销相对趋势20%、首销锁单率10%、档位/能源/发布类型各5%。缺项移除后归一；至少3项有效证据且必须有首销曲线形状证据才自动推荐。未结束车型只拿当前已观察部分评分，不用未来真实数据。历史完整曲线按目标首销周期适配后截取同进度。比较形状而不是绝对数量。 当前首销曲线按绝对日期落在D1～Dn，不用记录行号充当日期：缺失/重复日留空，后续日不前移，日历系数仍对应各自真实日期；共同窗口不完整时不提供形状评分证据。来源覆盖范围内已确认的零销量仍是有效0。
3. **平销承接**：按首销开始日对齐发布年龄，W1为D1–D7，W2为D8–D14。在当前待预测日期对应的发布周起点选择历史同龄4周窗口，计算“日历还原平销总大定日均 / 该历史车型全首销直接大定日均”的无量纲系数。只用七天都结束且真实锁单完整的平销周；缺日不补0、不把不相邻周当相邻。历史周只有锁单时，用该历史车型首销总大定到锁单率反推总大定，属于经验估算，不是订单级转化追踪。主辅加权后的系数乘本车型首销基准；缺可比窗口时按1倍并标为低置信度，不搬历史绝对销量。评分比较双方共同的完整发布周，图表按同一发布周横轴绘制，不再各自截取最近4周。本车型自己的近期真实销量仍用于当前量级校准。
4. **当前实际校准**：本车型最近最多7个完整平销日还原日均；有连续两组7日时比较周趋势。实际权重按最近连续有效日数/14增加，14日达到100%；日基准不可用时可使用有效完整周基准。全首销推算与真实平销按此权重组合，真实数据不足时不假装已经形成稳定趋势。
5. **趋势回退**：没有有效参考周趋势时，用全首销日历还原锁单等价值的 `log(1+日量)` 全期回归斜率形成周倍率，周对数倍率限制在[-0.7,0.7]，不足3日持平；明确标低置信度。首销和当前平销都无有效规模时停止，不凭历史绝对量生成结果。

KPI展示预测区间锁单合计（含已实现）、近期真实日均锁单、未来日均较近期实际变化率、当前主要依据；不再用四张卡片列四周绝对销量。周数量仍可在结论图中查看。

计算当前周起连续4个自然周的滚动区间；若平销尚未开始，从平销开始日所在周起算并剔除开始日前日期，因此首周可能不足7天。

```text
日趋势倍率 = 周环比 ^ (1/7)
滚动目标 = 四周区间内 Σ(日历还原日均量 × 日趋势倍率^距区间首日天数 × 该日日历系数)
待预测余量 = max(滚动目标, 区间内已实现锁单) - 区间内已实现锁单
```

以前一天真实交车锁单衔接，将余量分配到今天及未来日期，再按自然周汇总为“实际＋预测”。当天快照是下限，必要时重分配未来余量或抬升总量。即使图表仅展示滚动4周，也必须校验**平销开始日至昨天的全部真实日**；任何必要日缺失/异常或缺昨天真实锚点都会停止，不用预测覆盖窗口外的历史缺口。

### 不同周期的累计完成度适配

设历史有N天、目标有M天。D1、D2各日占比原样保留；历史D(N−1)、DN映射到目标D(M−1)、DM，也保留各日占比。中间从累计D2到累计D(N−2)，按M−4个目标日作线性插值，再差分得到日占比。中间总占比守恒，累计不倒退，末日100%。 整条目标曲线只拉伸一次，再逐日取值；单日查询和整曲线展示共用同一适配规则，不逐天重新拉伸整条曲线，不增加持久化缓存。

例如历史10天→目标18天：D1/D2不变，历史D3—D8映射到目标D3—D16，历史D9/D10映射到目标D17/D18。同长度直接使用；不同长度且任一周期不足5天不能同时保留四个端点，不自动推荐该完成度参考。历史实际不改写，仅改变参考适配。方法一完成度反推、参考图和到天基础分配使用一致的适配规则；缺尾段真实曲线不虚构终局。

顶部快捷车型按同车型最新年份筛选，最新年份的普通代际与汇总代际**都显示**；盲订、直订、预订、Beta等特殊项仍不进入快捷栏，下拉框保留。

### 三阶段共用的逐日分配

小订、首销、平销分别维护日历系数，默认工作日1、普通周末1.15、法定放假1.3，人工值必须大于0且不超过5；调休上班按工作日，超出已维护官方日历年度按自然周估计并提示。

先用参考形状、日历系数和已知锚点形成基础曲线，再按渐进差额权重分配剩余总量；默认权重为首个待预测日0、第二日0.5、以后各日1，结合基础量计算有效分配权重。小订锚点可为最近完整真实日或D1全天估算；首销以最近完整真实日衔接；平销开始后用昨天真实锁单。整数分配保持非负及合计一致，真实日不随参数改变。用户输入差额权重时，数量必须覆盖全部待预测日期且均非负；无效参数停止分配并提示。

网页人工参数和外部逐日预测仅作本机预测/对照，不回写原始Excel、不覆盖真实订单，也不将估算写成汇总中的已发生真实值。

## 销量预测实现详解

本节按当前代码区分“取数、终局计算、逐日分配、页面展示”。算例仅解释公式，不是任何车型的正式预测。修改网页参数不改写原始Excel，也不将预测值保存成汇总中的真实订单。

### 1. 从原始文件到页面

1. `main.py` 按配置调用刷新工具：解析历史整理表、车型映射及当前订单文件，按前述规则合并来源、校验字段，生成销量数据汇总；依赖签名未变可跳过刷新。
2. `SalesForecastModule.build` 通过 `summary_scope` 识别可见数据格式，进入 `_build_from_visible`。新版 `read_public_forecast` 读取已按字段选定的最终数量，不再由整理表覆盖一次。取数按生成时的绝对阶段判断，与网页选中的页面无关。
3. Python把历史参考、目标车型、分阶段真实记录及来源信息压缩写入HTML。浏览器点击、改参数时不重新打开Excel，而是用已加载的快照计算。

5. 原始数据更新后重新运行main，再刷新网页。草稿只恢复人工修改项，不覆盖本次生成的真实订单。

正常新版汇总路径不补读原始预测文件。代码仍保留“汇总不存在时从来源构建”和旧结构兼容分支；不等于删除了所有原始读取入口。缺表或结构异常时应重新生成汇总，不应手工补隐藏缓存。

`forecast_as_of_date` 非空时统一使用该日期。为空时Python用生成当天，浏览器用本机当天；跨日打开旧HTML可能出现判定日期已推进而真实数据未更新，应重新生成。复盘日期只切分现有数据，不恢复历史文件版本。

### 2. 先辨认指标，再看KPI

| 指标 | 定义及边界 |

小订D1的已发生KPI可包含当天分时累计；D1以后用于完整日反推的是昨天及以前。首销方法一参数区的真实累计不含今天全天外推，估算另列。图表以本次终局作分母时，调整参数可改变真实段百分比，但不会改变真实订单数量。

汇总参考区按“小订当日数量 → 小订累计完成度 → 首销D1D2预测指标”连续排列，新生成文件不再输出旧名D1_D2预测指标。

终值比例参数（小订转化率、直接大定占比、大定到锁单率、留存大定率）只使用有有效比例且对应口径无异常的参考。缺失比例保留为空，不转换成0；剔除缺失参考后，剩余有效权重重新归一。例如主参考70%但最终转化率缺失、辅助参考30%且最终转化率41.3%，推荐终值为41.3%，不是12.4%。两项都有效时仍按原主辅权重加权，真实0与缺失不同。没有有效终值则提示条件不足或人工维护，不用部分期累计比例冒充终值。

参考评分也遵循缺失不等于0：D1/D2结构占比、斜率与退订率从汇总读取到前端计算均保留空值；任一侧缺少该项数据，则剔除该评分项并重新归一有效权重。D1～Dn形状比较要求共同窗口内每一天的该指标完整，缺失不补0，真实0保留。有效的0%终值/退订率可以提供评分证据；锁单、留存率必须通过与参数建议相同的有效性检查。这不改变文件覆盖范围内省略零销量日期的既有补0规则。

评分覆盖充分但缺少对应最终比例的车型，不自动推荐为该终值参数参考；仍可作为图表对比。参考说明显示实际参与加权车型、有效权重和推荐终值。历史比例曲线按各自首销天数展示；进行中的历史车型曲线可能只是部分期实际进度，不能直接与预测终点比较。

方法二小转大终值＝总小订×有效参考转化率；直接大定终值＝小转大终值×直接大定占比÷(1−直接大定占比)。占比需在[0%,100%)内，不再静默限制在95%。实际累计突破原参数时按真实下限抬升，阶段已结束时采用真实终值；人工修改参数时保留人工值。因此方法二默认比例应接近有效参考加权值（仅有输入百分比/数量舍入差异），方法一按真实累计÷参考完成度独立外推，不能为接近参考而强制修改真实数或终局。

### 3. 小订与首销D1分时计算公式

取得当前D1已采集小时新增量，按发布后相对小时对齐历史曲线。发布前留空，不能强制从0时画起。历史曲线按当前发布后可用小时窗口重定基，再按主辅分时权重合成累计占比q。

设截至h时已发生量为O，最近最多3个已采集小时新增量为R、对应参考占比增量为Δq：

```text
累计进度量级 A = O / q[h]
最近时段量级 B = R / Δq
外推量级 K = (A+B)/2                 # Δq>0，否则只用A
未来小时量 F = max(0, round(K × (1-q[h])))
D1预计全天 = O+F
小订终局 = D1预计全天 / 目标窗口内的参考D1占比
```

F按历史后续小时占比增量分成非负整数。该外推不使用历史D1绝对销量。分时参考决定今天剩余小时，累计参考决定D1放大到整个小订期，两组参考可以不同。

例：O=600、q[h]=0.6、R=240、Δq=0.2，则A=1000、B=1200、K=1100，未来440，D1预计1040。累计参考D1占比20%时，总小订预计5200。纯累计完成率法会得到D1=1000，当前实现会响应最近小时较强的趋势。

23时参考累计已达100%时不再预测剩余小时。没有正数已发生量、有效参考曲线或累计D1占比时显示等待/停止原因，不伪造分时数据。

### 4. 首销两种方法的职责和算例

方法一分别用小转大、直接大定累计完成度反推两个终局。方法二分别用转化率和直接大定占比确定两个终局。两种方法共同使用“到天基础曲线”分配后续量，但各自的终局和剩余量独立。

例：首销来到D5，D1～D4真实小转大累计800、直接大定400，尚无有效D5快照：

- 方法一同期完成率分别40%、25%：C=2000、B=1600、G=3600，剩余2400。
- 方法二S=10000、c=30%、p=25%：C=3000、B=1000、G=4000，剩余2800。
- 两种方法均冻结已发生1200；各自的小转大与直接大定余量分别分配，逐日总大定再相加。

若今天有分时快照，先将今天全天估算作为独立预测行，再分配后续日期。因此首个待分配日不一定是今天。首销前D1专项预测也会先占用终局量。结束且真实完整时按实际收口，不再分配未来余量。

方法二计算时p需在[0%,100%)内，c需在(0%,100%]内；缺失或越界时该方法提示条件不足，不静默钳制参数。公式结果低于已实现或已采用的当日估算时，各分项分别抬升到相应下限，不能只提高总大定而让分项不一致；预计锁单也不得低于已发生真实锁单。

### 5. 到天基础曲线、日历和渐进差额

到天基础曲线不是“每天占终局的固定百分比”。小订和首销先取参考每日量，剔除该历史日期的日历系数，再相对历史D1归一并主辅加权，得到形状s。目标工作日、周末或假日系数f在分配时加入。首销两种方法均主要使用这组日形状，不用方法二的转化率曲线替代日形状。

首销到天基础曲线只接受**首销已经结束且整个周期逐日大定完整有效**的参考车型：开始/结束日期与首销天数须一致，结束日期须早于当前判定日（结束当天仍不算完整），D1大定须大于0。覆盖范围内已补齐的真实0销量有效；空白、负数或无效数量不当作0。不能把尚未结束或只收齐前半段的销量归一为完整终局，再拉伸到整个预测周期。自动推荐、人工主辅选择、草稿恢复及实际分配计算使用同一校验；无效参考剔除后，有效主辅权重重新归一。完整参考继续保留头两天、尾两天，中间比例拉伸且总量守恒。

未结束或未收齐的参考仍可在“图表对比车型”中勾选，仅展示截至判定日前连续有效的已发生走势，标明“仅已发生，不参与分配”，不拉伸成完整周期、不画未来真实值。该限制针对首销到天分配，不禁止已有有效真实指标的横向比较，也不禁止已经结束并通过完整性校验的D1分时参考。没有有效到天参考时保留原有通用基础形状回退，不把不完整历史当成完整参考；本次不调整终局公式、评分权重、日历系数或阶段取数优先级。

平销不借用首销逐日活动峰值形状，而是用周趋势换算的日趋势形状，加上目标日历。一天只属于一种日历类型：法定假日不再叠乘周末，调休上班按工作日。三阶段系数独立维护，默认工作日1、周末1.15、假日1.3。

设剩余总量为R，前一真实日数量a、其日历系数fₐ、其参考形状sₐ；待预测日i的形状sᵢ、日历系数fᵢ、人工渐进权重wᵢ：

```text
有有效锚点：基础量 bᵢ = (a/fₐ) × (sᵢ/sₐ) × fᵢ
无有效锚点：基础量 bᵢ = R × (sᵢfᵢ) / Σ(sⱼfⱼ)
差额 Δ = R - Σbᵢ
有效调整量级 uᵢ = wᵢ × bᵢ          # bᵢ>0；否则用wᵢ×fᵢ
正差额时：初步预测 yᵢ = bᵢ + Δ × uᵢ/Σuⱼ
```

这里“按前日延伸”不是把前一天数量原样复制到所有未来日期，而是保留前一天量级、随基础曲线和目标日历变化。有效调整量级已经包含日历影响，分差额时不再额外乘一次假日倍率。

负差额时按有效权重逐轮扣减，最多扣到0，剩余扣减继续分到其他可扣日期。若正权重日已不足以承接扣减，允许放开零权重日并提示；因此权重0代表优先保护，并非任何情况下绝对锁死。最终整数化保持总和R、每天非负。

默认权重为 `[0,0.5,1,1,…]`，第3个待分配日起封顶，不随剩余天数持续增长。它是调整参与程度，不是销量百分比，也不是最终差额占比；最终占比还乘基础量。人工填写时需覆盖全部待分配日。无锚点时基础量已按R归一，差额为0，渐进权重不会凭空创造额外趋势。

算例：D4实际100，后续4日形状及日历均为1，剩余R=500：基础量为 `[100,100,100,100]`，差额100；有效权重为 `[0,50,100,100]`，分到的差额为 `[0,20,40,40]`，预测为 `[100,120,140,140]`。D5不承担全部差额，且后几天权重不会无限变大。若D5为周末，其基础量先变为115，再按新的基础合计与R计算差额，而不是最后另乘1.15。

特殊边界：

- 只剩1天：该日承接全部剩余量，无法再渐进。
- 没有待预测日且R=0：正常结束；R>0：提示“没有剩余日期承接剩余量”。
- 差额非零但所有调整权重为0：停止并要求至少启用一个日期。
- 差额绝对值超过基础合计30%（且超过1单）：提示复核，不偷偷改终局。
- 今天已发生量超过今天预测：优先从未来余量重新分配；总余量不足时抬升终局。今天仍是未结束日。

### 6. 自动评分与主辅权重不是一回事

自动评分用于排列候选；主辅权重用于混合已选参考参数。把主参考权重从70%调成80%不会反向改变该车匹配得分。额外勾选的图表车型既不改变评分，也不参与预测加权。

小订累计/到天参考的5项为档位、能源、发布类型、小订天数、已知小订量级，对有效项等权平均，至少3项有效证据才自动推荐。历史最终总小订必须为正且不是未完成终值。D1分时独立评分：发布时间20%、小时新增归一化形状50%、累计占比30%；不看历史D1绝对量，缺项后按有效权重归一，至少1项有效证据。平销按全首销形状55%、平销趋势20%、锁单率10%、档位/能源/发布类型各5%加权，缺项归一；至少3项且包含首销形状证据，并需有效平销周历史。当前车型不作为自己的历史参考。

首销各任务的配置权重如下，百分比为评分权重而非销量分配比例：

| 任务 | 配置权重 |
| --- | --- |
| D1分时 | 发布时间20、已观测小时新增归一化形状50、已观测窗口累计占比30；不比较D1绝对量 |
| 小转大完成率 | 档位10、能源6、天数10、小订量级8、D1结构16、D2斜率12、Dn形状25、曲线13 |
| 直接大定完成率 | 档位7、发布类型7、星期5、时段5、天数9、D1结构16、D2斜率14、Dn形状24、曲线13 |
| 小订转化率 | 档位15、能源10、天数10、小订量级13、D1结构14、D2斜率10、Dn形状18、早期退订6、最终指标4 |
| 直接大定占比 | 档位10、发布类型8、时段6、天数8、小订量级6、D1结构17、D2斜率15、Dn形状20、最终指标10 |
| 大定到锁单率 | 档位20、能源8、天数12、小订量级12、早期退订18、锁单留存数据30 |
| 到天基础曲线 | 档位10、天数35、日历结构20、发布星期10、曲线25 |
| 每日斜率（展示任务） | 档位15、天数20、日历结构15、真实日环比相似度40、斜率曲线10 |
| 量级匹配 | 档位40、能源10、天数20、小订量级30 |

```text
有效总分 = Σ(有效单项相似度 × 配置权重) / Σ有效权重
证据覆盖率 = Σ有效权重 / Σ配置权重
```

首销覆盖率低于45%不自动推荐；缺失项一般移出分母，不按0分，也不补中性分。曲线可用性例外：缺失仍计35%相似度；锁单留存数据按两项有效字段计0%、50%或100%。因此有高分不等于证据足够，需同时看覆盖率。

小订进行中，首销评分的小订量级可引用同一车型、同一判定日、无错误的小订预测，并标注“小订预测”。例如首销尚无D1时，转化率任务在档位、能源、天数、预测小订量级、历史最终指标均有效时，覆盖率为52%；直接占比任务在档位、发布类型、时段、天数、预测量级、最终指标均有效时为48%。仍缺关键属性时可能低于45%，不能为了必出推荐而降低门槛。

“D1～Dn归一化斜率”在首销评分里实际比较的是累计形状：将双方截至同一Dn的小转大或直接大定分别归一到Dn=100%，比较前面各点，末点固定100%不比较；至少3个完整真实日。它不是对订单数量直接求数学导数。

“每日斜率”展示为 `当天量/前一天量−1`。首日、前一天为0或任一日缺失时留空；评分中的真实日环比相似度还会先剔除日历影响，至少需要2个有效比值。这个展示任务可选主辅并打分，但不参与首销方法一/二的终局和逐日分配。

### 7. 平销和跨阶段联动补充

小订预测传给首销方法二，不要求先到首销期；方法一仍需实际进度。小订结束当天也允许联动，不提前要求真实终局。平销尚未开始时，首销方法一可用则优先，否则取方法二，再用其全首销直接大定曲线和大定到锁单率估计平销量级，不是把整个首销总量当成一个平销周。

平销已有真实日后，最近日基准优先于完整周基准，因此本周尚未结束，但本周已经结束的几天也参与。日量先除以日历系数；有连续前后两组7日才能按两组均值算周趋势，否则日基准趋势按持平。周基准则用周锁单除以该周7天日历系数之和，最近最多4周求均值，最近最多4个有效周环比求均值。

平销周显示包含实际和预测：假设周三运行，本周一、周二为实际，周三至周日为待预测；周三已有快照作为当日下限，不当成完整真实日。首个平销周若从周中开始，只统计平销开始后的日期。跨首销/平销的周不得把整周原值重复记入两个阶段，缺少完整日拆分依据时相关周字段留空并告警。

### 8. 常见提示与核对顺序

| 提示/现象 | 先检查什么 |
| --- | --- |
| 有效指标覆盖不足 | 车型档位/能源/发布参数是否维护，历史指标是否有效，小订预测是否已联动；不是只看候选数量 |
| 总小订缺失或不大于0 | 小订是否确实已结束；进行中查看预测等待原因，结束后核对真实来源终值，不能拿当前累计冒充 |
| 已结束日缺失 | 汇总日期范围和字段是否真的可用；先区分覆盖范围内省略的零销量日、显式空白、尚未更新的日期 |
| 没有剩余日期承接剩余量 | 阶段起止日、已用日数量、终局与累计是否一致；不要再补一条虚假日期 |
| 某参考可选但无法自动推荐 | 有效证据数/覆盖不足；人工选择不代表该参考缺失的数据变成可用 |
| 分时车型不显示 | 是否有该事件真实D1小时曲线；无曲线的选项明确禁选，不用日数据伪造小时曲线 |
| 导入后只有一个点 | 当前车型、当前阶段、导入范围只匹配一天；多个日期才形成折线，不能伪造第二个日期 |
| 打开旧网页后出现缺日 | 浏览器日期已跨日但HTML仍是旧快照；重新运行main并刷新，而非清空真实校验 |

先核对车型/传播事件和阶段日期，再看汇总字段及来源，最后查参考选择和人工参数。真实0与空白不同，优先来源缺值可以按规则回退；停止预测应是必要数据在有效回退后仍不足，而不是首个来源没找到就立即报错。

#### 前后端计算与校验的边界

- **Python负责数据准备**：Excel取数、来源优先级、历史实际指标、来源校验及页面载荷。历史转化率、完成度等是已发生数据的统计，不是另一个未来预测引擎。不要在生成时复制一套网页终局公式。

- **`dashboard.js`负责页面编排**：选择参考、获取输入、同步草稿、阶段联动、调用计算并渲染。它仍包含部分评分、逐日构造和交互编排，不宣称本轮已将所有预测计算全部拆出。CSS仅控制展示，不计算销量。
- **阶段判断两端有必要的用途，但必须保持同一约定**：Python生成时选择来源，JS在用户修改日期后即时重算。D1包含开始日，结束当天仍在阶段内，次日才结束；明确开始/结束日期优先于维护天数；日期倒置或无效不得偷偷用天数回退。没有结束日期时只接受正整数天数。JS按UTC日期算天数，避免浏览器时区及夏令时改变结果。`test_forecast_contract.py` 将同一批开始日、结束日、跨年、闰日、冲突日期等案例实际交给Python和Node执行并比较结果。

6. **首销平销by周**：同代际同ISO周一行，保留大定、留存大定、交车锁单和来源。完整平销周优先原始by周；首销先汇总已解析日数据，不完整时回退完整周原值。跨阶段周在同一行保留首销/平销分段和合计；普通周不重复填分段。某分段不完整时整周相关合计留空，不把半周当整周。跨阶段周不能作为完整平销周参考。

更新原始Excel后运行main.py即可刷新。汇总中的明细为生成时快照，请在原始文件修改业务数据；直接编辑生成明细会在刷新时被覆盖。网页参数仍在网页人工调整，不将预测值写成已发生真实订单。单独运行刷新脚本可用 `--orders 当前订单目录` 和 `--as-of-date YYYY-MM-DD`。旧名称仅保留兼容读取。

预测汇总只收录预测需要的数据，不复制SKU、选配金等明细。小订/大定/锁单选配比例表中，文件真实覆盖范围内省略的日期按0，包括老车型连续无销量；不能只用某车型最后售出日期判断文件截止。多文件合并时保留这一省略日期含义，显式空白仍可回退。文件未更新的尾部、没有文件覆盖证据的日期和未来日期不补0。字段完整度和质量基准随最终数量刷新。

历史参考曲线先按完整代际名／二级代际名精确匹配；旧名称只在能唯一确认事件时兼容。空白日期只能由同一事件的可靠来源补齐，不跨版本复制曲线。无终值的小订部分历史保留真实数量，但不充当终局预测参考。首销已结束时优先完整日锁单合计，汇总已确认终值只补缺。首销“已结束日真实小转大/直接大定”不包含当天全天估算。当天只有大定总数而缺少分项时，分项仅作估算且保持加总一致；两种方法的整数终局与逐日合计一致。D2以后分时滚动优先用本车型最近最多7个完整非D1日、同日历类型优先的分时曲线；否则借用历史D1并提示低置信度。分时比例的分母为同日实际总量或当日预计全天量，不混用其他日期。小订和平销未结束日的已发生量是预测下限，不计为完整真实日。

汇总生成在内存中完成来源整合和计算，只写入最终可见数据表，不再创建隐藏业务缓存；原始来源Sheet仅在生成期间使用，不保留在最终文件。最终文件通过临时文件原子替换。刷新签名存放于普通工作簿属性 identifier（仅失效校验哈希，不含预测数据），来源变更和跨日失效规则不变。

如需每次运行 `main.py` 前自动刷新，将 `config.json` 中以下配置改为 `true`：

```json
"refresh_sales_forecast_data_before_build": true
```

`build_manifest_mode` 控制诊断清单：`off` 为默认高性能模式，`compact` 为紧凑 JSON，`full` 为带缩进的调试格式。
