# 鸿蒙智行订单分析

订单分析与同级 `销量预测/` 项目已完全分开：两者独立维护代码、配置、模板、生成结果和缓存。它们只读取相同的共享业务输入，不互相导入代码，不调用对方入口。销量预测的完整使用说明位于其项目 `scripts/generate_html/README.md`。

源码中暂保留的旧预测模块、工具、渲染辅助函数及历史回归测试仅为停用的本地兼容副本，不注册到订单入口、不在订单构建中调用，也不与新项目同步。订单页不加载预测计算或导入脚本。后续预测功能修改应只在 `销量预测/` 项目进行。

## 运行

从本项目的 `scripts/generate_html/` 运行：

```powershell
python main.py --no-open
```

输入按本项目位置定位到 `../共享数据/订单汇总/`，车型信息位于 `../共享数据/车型信息/`；路径不依赖当前命令行目录。不在代码中写入本机盘符。`SHARED_DATA_ROOT` 可指定共享根目录，推荐相对值 `../共享数据`，统一相对于“订单分析”项目根目录解析，也兼容绝对路径。显式 `--input` 和 `--output` 可覆盖本次输入和输出，其相对值仍按运行命令时的当前目录解析。

默认只生成本项目 `output_file/鸿蒙智行订单分析汇总.html`；日志位于 `output_file/log/`，运行缓存位于输出目录 `.cache/` 并在结束后清理。共享输入只读，不生成或覆盖共享销量汇总，也不清理共享目录缓存。旧 `--disable-sales-forecast` 参数仍可接收，但本项目始终不运行预测。

```text
工作区/
  共享数据/
    订单汇总/                   业务 Excel，只读
    车型信息/                   车型资料，只读
  订单分析/
    scripts/generate_html/      本项目代码、配置、模板和测试
    output_file/                本项目 HTML、日志和临时缓存
  销量预测/                     独立预测项目，不作为本项目依赖
```

共享根已指定或同级存在时，缺失文件不会从旧目录逐项回退。没有共享根的旧部署仍支持 `output_file/` 输入布局。不要直接编辑自动生成 HTML，也不要将整个 `output_file/` 当临时目录删除。

## 输入文件与主体识别

普通看板扫描输入目录**当前层级**的 `.xlsx`，不递归扫描子目录，忽略以 `~$` 开头的Excel临时文件。业务分类主要由文件名关键词确定，主体、时间粒度和用途再由Sheet名称及表头识别。不是任意Excel放进目录就能自动变成同样的业务分析。

| 文件名包含的关键词 | 主要用途 | 常见Sheet结构 |
| --- | --- | --- |
| 大定选配比例 | 订单总览、大定选配 | 主体名＋by天/by周/by月，及对应图表Sheet |
| 锁单选配比例 | 订单总览、锁单选配 | 主体名＋by天/by周/by月，及对应图表Sheet |
| 小订选配比例 | 小订选配、小订节奏 | 主体名＋by天/by周/by月，及对应图表Sheet |
| 首销期订单节奏 | 首销节奏 | 一级或二级代际名＋by天/by时；多版本按二级代际区分 |
| 小订退订 | 小订节奏 | 主体名_日度退订、_小订分时退订、_选配退订 |
| 订单7级转化 | 同批订单转化漏斗 | 周/月周期及七个阶段的数量表头 |
| SKU收敛度 | SKU集中度与组合 | 主体名_SKU、主体名_组合等 |
| 选配金统计 | 选配金额、付费占比与权益 | 选配渗透率、付费选配占比、渗透率排名等 |

同类文件可以同时存在，例如不同年份的大定选配比例文件，全部纳入；重叠值不默认累加。

主体分集团、品牌、代际，由原始Sheet动态发现。不要求新车型出现后手工修改快捷按钮名单。每个主体的可用模块和粒度取决于实际数据：缺少所需表型会使模块不可用，不能强行展示空看板。

销量汇总和预测整理表不参与订单模块或底表中心；阶段身份仍按共享整理表识别。

Excel公式以文件保存的缓存结果读取，Python不会启动Excel重新计算公式。公式显示有值但程序读不到时，应先在Excel中重算并保存，再生成。数字、日期和百分比应保留原始类型及格式，不要为了页面显示把数量列改成带单位字符串。

## 看板模块说明

### 订单总览

回答“当前周期下单、留存、锁单和交付怎么样”。支持实际可用的日、周、月，核心KPI为大定、留存大定、交车锁单、已交付。

当前总览要求同主体、同粒度的大定选配与锁单选配数据同时存在，周期取两者交集并排除总计等汇总标签；只有一类文件或周期未对齐时，不一定能构建该粒度总览。

- 大定、已交付主要取当前主体的数据Sheet；留存大定和交车锁单的趋势及总览口径优先使用对应图表Sheet数据，具体来源可点开核对。
- 展示留存大定与交车锁单趋势、门店渠道锁单量、可用的锁单结构，以及周/月经营指标与环比。
- 集团层增加符合条件的车型涨跌幅排行；总计/累计等汇总周期不当普通周期参与该排行。
- 集团/品牌自身KPI并不是把页面列出的所有代际再次求和，避免“汇总代际”和分代际重复计算。
- 总览口径校验用于发现数据Sheet、图表Sheet或结构分项的不一致。出现警告先比对相同主体、粒度、周期、指标，不能只因数值不同就改成相加。

### 渠道分析

位于“订单总览”下方，支持集团、五个品牌及原表中已有的车型代际，按日、周、月查看渠道销量和门店表现。各主体直接读取自己的“大定选配比例分析”Sheet，不把各车型的出单门店数相加作为品牌门店数。

三个板块分别展示：

- **各渠道留存大定及占比**：直接采用“门店类型”指标下的“数量”和“占比”，左侧常显两张历史表，右侧用各渠道占比堆积柱和留存大定总量折线展示变化。不重新分类门店、不归一化原始占比。
- **贡献订单门店比例**：读取“门店类型”下统计类型为“贡献门店数”的渠道数量；出单门店比例＝该渠道当期出单门店数÷该品牌该渠道总门店数。各渠道比例使用历史表和多条折线展示，不堆积。周、月和品牌级门店数须由上游按相同订单口径去重，不能累加每日或各车型的门店数。
- **单店产能**：该渠道本周期留存大定÷该品牌该渠道总门店数，单位为单/店。历史表和多条折线同时展示所有渠道。日、周、月均表示本周期产能，不额外除以周期天数。

在 `modules/channel_analysis.py` 顶部修改全局变量 `CHANNEL_STORE_COUNTS`，结构为“品牌 → 渠道名称 → 总门店数”，例如 `CHANNEL_STORE_COUNTS["问界"]["华为授权体验店"]`。五个品牌分别采用提供的授权门店数量，车型默认继承所属品牌；`CHANNEL_STORE_COUNTS_BY_SUBJECT` 可按主体名配置部分渠道覆盖，不从其他品牌回退。修改后重新运行 `main.py` 生效；这些配置按固定门店数应用于全部历史周期。

集团各渠道总门店数按五个品牌的生效配置相加，包含品牌覆盖配置；共用门店也按各品牌分别累加，不叠加车型或集团覆盖配置。未配置的渠道不会被当作零门店，也不会自动归到其他渠道。

### 小订节奏

回答“小订如何随天/小时变化、留存与退订发生在哪里”。当前构建需要同主体的小订选配by天和日度退订，分时与选配退订表按可用情况增加展示。

核心KPI为小订期累计、累计留存小订、累计退订和阶段留存率，附日节奏、分时以及可用的选配退订分析。

必须区分“按小订日期追踪的退订”和“取消发生日的退订”：分时退订可按下单日期聚合订单及其退订；日度退订反映当天取消的订单，可能并非当天新下单。不能用“当天下单−当天取消”无条件推导同批留存。分时缺相应日期时有日度退订展示回退，但来源不同，不应把两者视为同一批次指标。

当前代码逐日留存实际按 `max(该日采用的小订量−该日采用的退订量,0)` 计算，再求阶段合计；退订有分时按下单日期聚合值时优先使用，否则回退日度值。因此发生回退时，该页留存是这个混合来源算法的结果，不能宣称已经完成严格的同批订单留存追踪。

### 首销节奏

回答“首销已发生的订单来自小转大还是直接大定、转化走到哪里”。展示累计大定、累计锁单、累计小转大率、累计直接大定占比、完整指标矩阵和可用的小时节奏。

“首销订单来源”图按当日直接大定和当日小订转大堆叠，柱顶为当日来源合计，不读取累计数量；周视图对应当周来源。比例线展示累计小转大率（累计小转大÷总小订）和累计直接大定占比（累计直接大定÷累计总大定），全部已知点保留数据标签；曲线上方不再显示摘要名称、最新值和截止周期。缺失分项保留缺口，不用累计值替代。累计占比卡片、曲线和指标表使用同一组数量口径，多阶段视图同样按各期独立展示当期来源。

统一口径：每日直接大定占比＝当日直接大定÷当日总大定；累计直接大定占比＝累计直接大定÷累计总大定。周视图按当周直接大定÷当周总大定展示对应周期占比。累计小转大率＝累计小转大÷总小订。支持已识别的多期首销：各期独立计算，并可展示多期汇总；多期小转大率按各期总小订加权；多期累计直接大定占比用各期已知累计直接大定合计÷累计总大定合计，不直接平均各期百分比。这是实际节奏分析，与销量预测里的未来估算分开。

### 订单7级转化

顺序为：大定 → 留存大定 → 销售锁单 → 交车锁单 → 已发运 → 已到店 → 已交付。按周/月订单批次读取，同一行追踪同一批订单，不代表七个阶段各自当天新发生量。

```text
总转化率 = 本批已交付 / 本批大定
某阶段总占比 = 阶段数量 / 本批大定
阶段转化率 = 阶段数量 / 前一阶段数量
阶段流失 = max(前一阶段数量 - 阶段数量, 0)
```

展示漏斗、批次矩阵、最大阶段流失及流失占比。大定到交车锁单、交车锁单到交付的时长按源表读取，不从数量反推。列按表头名称识别，缺少七阶段必要表头时不按固定列号猜测；时长字段缺失则留空。普通模块部分数值使用安全转换和除零保护，页面0不一定证明原表明确填写0，排查时需看底表，不能套用预测模块更严格的缺失处理结论。

### 大定选配、锁单选配、小订选配

三页共用结构分析逻辑，但订单母体不同：大定选配关注大定/留存大定，锁单选配关注交车锁单/已交付，小订选配关注小订/留存小订。不要把三页同名配置的占比当作同一个分母。

展示外观、内饰、版本、能源、电池等实际存在维度的结构全景、各维度TOP1、偏好变化排行及可用的电池包周/月历史。核心结构KPI包括维度数、活跃选配项、最高配置占比、高集中维度数和最大结构变化。

占比变化以“百分点”表达，例如20%到25%为增加5个百分点，不是增长5%。高集中维度按TOP1占比≥50%判断。多个不同维度分别描述同一批订单，不能把外观占比与内饰占比相加成总占比。

### SKU收敛

回答“销量是否集中于少数完整配置组合”。展示有效SKU、TOP3/TOP5累计锁单占比、覆盖80%所需SKU数、TOP1～TOP15周度累计占比、组合热力图、排行和长尾分布。

SKU是配置组合，不等于单一外观或内饰选项。长尾分布关注单周占比≤5%的SKU。跨文件合并数量不代表TOP排名、覆盖80%所需SKU等非加法指标也能直接累加；不能从缺少完整组合分布的数据猜出新的收敛排名。

### 选配金

回答“用户选了多少金额、实际支付多少、权益影响及选配渗透率如何”。代际页展示平均选配金额、平均实际金额、最高付费选配占比、权益金额，以及金额段月度结构、选配项热力图、权益和版本金额对照。

品牌页侧重覆盖代际、高频选配项、金额段结构和汇总KPI。需注意品牌“平均选配金额”当前为有效版本金额的算术均值，不是按订单量加权的客户均值。权益金额与实际支付并非同一指标，不能把权益直接当收入，也不能把渗透率当付费率。

不同车型金额段可能不同，页面按存在的金额段对齐；月度表保留月份及金额档位两层含义，不能把总计列错认成某个月份。

### 导入分析

用于检查“哪些Sheet被识别、被哪个模块使用、哪些结构尚需配置”。展示已识别数据、待归类数据及需核查状态，如无数值、疑似只有表头、尚未被看板使用等。

这里的“导入”是生成时扫描Excel，不是网页上传原始业务文件。未知结构仅提供通用预览，不承诺自动生成正确业务口径；预览最多取前80行、24列，数值计数也有预览范围限制，不能据此判断整表规模或总量。

### 底表中心

用于按文件、Sheet查看源单元格，搜索、冻结行列及导出CSV。保留常见Excel数字格式的显示含义，便于从图表来源定位数据。

底表是生成时嵌入HTML的数据快照，不会直接修改原Excel，也不保证完整复刻合并样式、图片和所有Excel高级对象。业务看板合并多文件后，底表仍保留原文件供追溯；不要把原文件的重叠行再次累加。


## 页面操作与来源追溯

切换集团、品牌、代际后，只显示当前主体可用的模块与日、周、月粒度。看板来源抽屉可跳转底表中心，底表支持搜索、CSV 导出和完整原始 Excel 下载。更新 Excel 后需要重新生成 HTML；刷新浏览器只会重读已有快照。

## 配置与诊断

`config.json` 控制标题、`module_order`、`module_labels`、`grain_labels`、`chart_render_mode`（generated 或 original）和 `build_manifest_mode`（off、compact、full）。不再包含预测开关或预测日期。即使旧配置带有预测模块，订单入口也会排除它。

`--debug` 输出详细读取日志；`--check` 在有校验告警时返回非零；`--no-open` 禁止生成后自动打开页面。异常需核对对应输入文件、Sheet 和业务口径。真实 0、未知值与重叠来源不能随意合并。

### 同类多文件合并

输入目录下所有匹配类型的 `.xlsx` 都参与读取，忽略 `~$` 临时文件。同类不同年份的文件按原文件路径排序（同目录即文件名顺序），不是按修改时间选“最新文件”。

- 已识别表型按车型/Sheet、指标标签及日期或周期对齐；同类 Sheet 名仅忽略空格差异，保留不同首销期标识。订单7级转化按周期、分时小订按日期和小时、日度退订按日期识别记录键，不按固定列号拼接。选配金保留月份与金额档位两层表头，每月汇总列不移到其他月份。
- 同一业务位置取排序后首个非空值，后续文件只补空白。真实 `0` 有效，不被后续非零值覆盖；相同值去重，不重复累加。图表数据同样先完成空白回退，再按原展示规则处理仍无数据的位置。
- 重叠位置数值冲突时保留首个非空值并按文件类别汇总记录“多文件数值冲突”日志；普通日志只输出多文件合并概览，`--debug` 才列完整文件名。不会把年度文件中的总计相加，也不会自动把不同首销期合并成一场活动。
- 不同日期取并集，来源保留所有参与文件；底表中心仍可查看原始文件。未知表型保留各原表，不强行套用合并规则。
- 同代际跨年平销文件合并成一份历史，避免被当作多辆参考车重复加权。
- 选配比例明细合并时，指标名称“净大定”和“留存大定”沿用总览的兼容口径，统一按“留存大定”对齐，避免旧年/新年形成两行。只统一已识别指标的名称，不改变数量，不修改原 Excel，也不把“大定”并入。前提是原表实际业务口径相同；如果退订扣减范围不同，不能靠改表头把不同口径变成同一指标。

周数据的例外：按 ISO 周（周一至周日）判断跨 12 月 31 日的周，或跨 6 月 30 日且该日不是周日的周，但“是边界周”只是必要条件。只有两个原始文件的实际数据范围在边界处准确衔接（一个截止 6 月 30 日/12 月 31 日，另一个从 7 月 1 日/1 月 1 日开始），同一业务数量字段的不同有效值才相加。范围从文件内有有效数量的逐日日期判断，无需人工维护；也支持已有明确导出起止日期。若文件本身已跨半年/跨年、日期范围重叠、有间断、与该边界无关，或只有周标签无法确认范围，均不累加，保留原优先级并提示冲突。不能凭文件名年份猜范围。第三个文件重复同一半段不再追加。来源范围随汇总暂存目录传递，不能按文件名猜测。

例如 `26WK27`（2026-06-29～2026-07-05），文件A实际截止6月30日、文件B实际从7月1日开始时，140与90合为230；文件A已覆盖到7月5日时，不会再加文件B的90。跨年同理。`26WK53`、`2026WK53` 和大小写差异统一为同一周。相同值仍去重，普通周、日/月、年度总计及同文件重复键不适用此例外；真实零值可以参加加法，非法数、负数、非有限数不参加，明确空白/未来未填的日期不充当真实范围证据。

范围识别优先使用整份文件中非图表 `by天` 明细的有效数量日期及已有明确导出起止日期。`by天图表` 可能只展示最近30天，不能缩短或扩大已有明细范围；仅无有效明细/声明日期时，才回退读取逐日图表所有主体块各自的日期表头。日期支持 Excel 日期、日表头中的 Excel 序列日期、四位/两位年份文本和中文年月日。`26WK01` 对应 2025-12-29～2026-01-04，同样适用跨年衔接规则。

低销量老车型可能连续多日没有订单记录，不能用该车型最后一次成交日期代替整份文件的覆盖截止日期。范围取同一物理文件中所有可识别逐日表的有效日期并集，包括其他车型、品牌/集团汇总及明确的零数量；因此不要求每个车型都在边界日成交。若整份文件也缺少边界日期证据，仍无法区分零销量缺日与未导出日期时，不人为补出文件起止日期、不盲目累加，按普通冲突优先级处理。

该例外同步作用于选配比例表中的数量、订单7级转化的数量及趋势图总量。占比不直接相加：有对应分类数量时由合并分类数量重算，否则有主指标数量时按各片段数量加权；图表占比按各片段总量加权。缺少必要分母时保留原优先值及冲突提示，不猜测分母；平均时长、均价等非数量指标仍保留原优先值，不直接相加。INFO 日志用 `[边界周累加]` 按类别汇总周日期范围、跨年/跨半年原因、数量字段数、来源文件、各文件实际日期范围及最多3个加法示例；重复读取同一图表不重复打印累加日志。底表中心的原始文件保持不变。

未合并的图表真实冲突逐项列出主体、指标、周期、双方文件与原始单元格；边界周还给出文件实际范围和未累加原因，不再截成3个周期示例。已完成同一图表校验的读取复用不重复运行校验。SKU数量块遵循同样的边界周规则，但TOP3/TOP5、80%覆盖所需SKU数等收敛指标不能把比例或排名直接相加，仍保留原优先值并说明口径；不从不完整的SKU分布猜算新的收敛排名。
